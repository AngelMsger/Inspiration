# 本地验证

在一台电脑上运行 Inspiration：持久化数据库、本机负责人身份、DeepSeek 阅读与回答，以及
本地向量和重排模型。本模式落实产品负责人 2026-11-11 的决定，直接连接自建 Confluence
Data Center / Server 和飞书文档验证。[English](../local.md)。

## 启动

使用 macOS、Linux，或 Windows 上的 WSL2。需要 Node 22.18+（建议 24）、pnpm 10.28.0、
Python 3.10+ 和 Docker Compose；先启动 Docker Desktop。本地向量和重排模型需要数 GB
空间，首次使用会从 Hugging Face 下载。

```bash
make install
npm ci --prefix infra/local-embeddings
cp .env.example .env
# 在本机编辑 .env，填写 DeepSeek Key 和下述连接凭据。
pnpm local
```

打开 <http://localhost:4200>，选择“进入 Inspiration”，创建企业，再创建一个由自己负责的
空间。首轮验证建议保持空间私有。启动器会启动 Compose 服务、构建网页、启动已安装的
解析服务，并启动本地模型、引擎和业务后端，等待应用服务就绪。Ctrl+C 会停止应用进程，
数据库、队列、文档版本、文件、会话和用量保留。`make down` 也保留 Docker 卷；
**不要用 `make clean` 停止日常运行，它会删除数据卷。**

这是明确启用的单人本地模式，只监听回环地址，无需 Logto，不应通过公网代理暴露。
本机的每个浏览器都可以作为同一个负责人进入。托管和多人模式仍使用 OIDC 后端。

提供模型 Key 前，可以运行 `pnpm local --mock` 演练流程：它使用确定性的模拟模型、独立
Compose 项目和 55432、56379、55051、58443 端口。模拟结果不能用于判断模型质量。
请勿把模拟模式的数据库或权限服务指向真实模型使用的实例。`--skip-stack` 供开发时复用
已经运行的服务；真实模式默认使用普通 Compose 端口。

## 连接 Confluence

在 `.env` 设置 `INSPIRATION_CONFLUENCE_URL`，填写站点根地址；若站点有 `/confluence`
路径，也要包含。`INSPIRATION_CONFLUENCE_TOKEN` 填写能读取目标空间的账号的个人访问令牌
（PAT）。使用 Data Center / Server 的 `/rest/api/content` 和 Bearer PAT 认证；此版本不支持
Cloud、浏览器 SSO Cookie 或尚不支持 PAT 的旧服务器。若公司使用自签发证书，在启动 Node
前通过 `NODE_EXTRA_CA_CERTS` 指向公司 CA；需要内网时先连接 VPN，不关闭 TLS 校验。

进入“维护空间 → 文档连接”，选择 Confluence，填写连接名称和一个空间标识，例如 `HR`，
不是空间显示名；选择治理级别，再点击“连接并同步”。它会导入该账号在空间中可见的页面，
保留渲染后的 HTML、上级路径、版本和原文链接。此版本不导入附件、归档页面，也不保证
读取需要浏览器交互状态的宏。

## 连接飞书

使用已发布的飞书企业自建应用，设置 `INSPIRATION_FEISHU_APP_ID` 和
`INSPIRATION_FEISHU_APP_SECRET`。授予文档读取权限（`docx:document:readonly`，或开放平台
显示的对应文档读取权限）；使用知识库链接时还需要 `wiki:wiki:readonly`。
将应用添加为目标文档协作者，或通过知识库授权访问。仅开通 API 权限并不等于能读取某篇文档。

在文档连接页选择飞书，粘贴完整 `https://<企业>.feishu.cn/docx/<token>` 或 `/wiki/<token>`
链接，每行一个。知识库链接会解析为 docx 文档；这里导入明确指定的页面，不递归导入整个
知识库。文档块保留原生 ID 供引用；所有分页固定在同一文档版本读取。暂不支持表格、多维
表格、旧版 `doc` 文档、真实审批数据，以及附件和图片 OCR。

两种连接都读取凭据可见的内容。导入内容对 Inspiration 目标空间的读者可见，**不会复制
来源系统的逐篇权限**。凭据只在 `.env`，不会进入浏览器请求或来源记录。修改凭据后重启
本地应用。原文链接不会授予额外的上游访问权限。

## 完成一轮验证

1. 连接少量文档，先用几份制度，不要直接导入全公司知识库。
2. 查看持久保存的同步结果，再进入“文档”检查解析、索引和阅读进度。同步成功只表示
   内容已获取，模型可能还在后台阅读。
3. 需要比较事实的制度选“严格”。普通资料默认“宽松”：索引后可搜索，回答用到相关
   段落时进一步读取。“仅检索”不抽取事实。
4. 提问并打开引用，同时核对导入段落和原文链接。
5. 修改上游文档，点击“立即同步”，重新提问。未变化的文档不增加版本；变化的文档
   保留旧版本及其引用。
6. 加入相互冲突的严格级别陈述，检查负责人的待办、审阅证据并处理。模型发现的事实
   是候选判断，不等于已经确认的企业制度。
7. 重启 `pnpm local`，再进入同一企业检查文档、引用和连接结果。中断的同步会标为失败，
   提示重新同步。两个同步 API 入口共用 source-sync 的任务和持久化结果；并发请求复用正在
   执行的导入。飞书单篇读取失败会单独报告，其他文档继续更新，失败文档保留上次导入的版本。

空企业会从逐字引用的段落提出事实目录，按空间和敏感级别隔离保存。普通抽取仍校验证据；
治理规则要求人工决定的事项仍交给人。每个空间、每个敏感级别最多 200 个候选属性。
新主题约每分钟在后台整理一次，默认交给该空间的第一位负责人；尚未形成主题的小规模
材料，其复核也交给该负责人。搜索和引用无需等待主题整理完成。

`--discover-facts` 只控制目录发现。HTTP/MCP 服务独立启用按需阅读；空间负责人兜底路由和后台
主题组织也可与已有目录配合使用。提取组件按引用指定的文档版本解析段落，包括从旧版沿用的
span。回答前只把本次阅读提交的原始事件交给已有的治理与新鲜度处理器；后续总线投递依靠
相同事件 ID 幂等处理。回答不会等待无关的后台队列。

飞书 wiki 来源使用 wiki 页面 token 作为稳定身份，不随底层 docx token 改变。较早草稿中按
解析后的 docx 身份导入的 wiki 页面，会在下次同步时按 wiki 身份重新导入一次；历史版本和引用保留。

## 排查

- **连接不可用：** 补齐对应的两个 `.env` 设置并重启。连接表单不填写秘密。
- **401 / 403：** 检查 PAT 过期、应用发布、权限和文档授权。界面显示 HTTP 状态或飞书
  错误码，不显示服务器响应正文。
- **429、网络或 VPN 故障：** 恢复访问后重试。不完整的列表不会当成空来源。完整的
  Confluence 列表反映账号当前可见的页面，因此失去可见性的页面会在本地标记为移除。
- **阅读暂停：** 检查模型 Key、余额、本地模型下载和阅读提示；每 15 分钟自动恢复尝试。
  `config/gateway.trial.yaml` 限制每日阅读、回答和每月合计费用，用量重启后保留。
  默认云模型仅允许读取公开和内部级别内容。
- **首次处理很慢：** 第一次导入会加载 CPU 模型。模型服务的终端日志会显示下载失败；
  恢复 Hugging Face 访问后重试。
- **端口被占用：** 停止先前的应用，或修改 `.env` 中的端口。自行管理服务时，数据库、
  Valkey 和 SpiceDB 的连接地址也应保持一致。

API 参考：[Confluence REST](https://developer.atlassian.com/server/confluence/rest/v900/)、
[飞书 docx](https://open.feishu.cn/document/server-docs/docs/docs/docx-v1/guide)、
[DeepSeek](https://api-docs.deepseek.com/en/)。
