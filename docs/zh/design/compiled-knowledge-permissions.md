# 汇编知识的权限

状态：提议，2026-10-26，回应产品负责人在总览上的评论。总览已经按本文修改；最后一节的取舍等待产品负责人确认。已设计、尚未实现。本文是 [docs/design/compiled-knowledge-permissions.md](../../design/compiled-knowledge-permissions.md) 的中文副本，两者不一致时以英文版为准。

## 问题

Inspiration 从许多来源汇编知识：一个页面、一个流程、一个主题摘要或一个回答，会把多个空间里文档中的陈述组合起来，而读者各自能读的空间并不相同。两种简单的做法都行不通。

- **按读者删减会扭曲原意。** 从为别人写的文字里去掉读者无权看的部分，会改变它的意思。如果来源论述了正反两面，读者却只看到一面，页面就把读者引向了来源从未得出的结论。知识库的承诺是正确，不能这样做。
- **整体屏蔽既不可用，也可能被滥用。** 只因一个输入受限就隐藏整个页面，会让大部分人看不到知识库的大部分内容。更糟的是，任何人只要把一个无关紧要但权限严格的条目关联上去，就能让一大片知识对别人不可见。

下面的设计同时守住两点：读者看到的内容从不被悄悄扭曲，受限的输入也永远不能隐藏不属于它的知识。

## 原则

1. **受众由人决定，从不由输入决定。** 一个汇编单元的受众就是它所在空间的受众，或者它的维护人选定的更窄的受众。使用、关联或引用一个输入，从不缩小谁能读这个单元。
2. **为受众而写，从不按读者删减。** 编译器只用这个单元全体受众（按各自的许可级别）都能读的输入来写。受众读不到的输入，要么逐条放行给这个受众，要么不用。
3. **改变意思的省略需要人来决定。** 引擎能看到每一个输入。当它为某个受众省略一个输入时，会检查这个输入是否会改变单元所说的内容。如果会，单元不会被悄悄发布，而是由人决定。
4. **告诉读者，而不是误导读者。** 省略了重要内容的地方，读者会看到一条说明，指出这里有省略以及可以问谁，但从不透露内容。读者能看到的单元里不允许出现悄无声息的空缺。
5. **机密材料留在原处。** 标为 `secret` 的材料从不作为它所在空间之外任何东西的输入，空间之外也没有任何东西暗示它的存在。它的维护人可以有意地放行某一条陈述。
6. **替代依据只会增加可见性。** 一条陈述有多个独立依据时，读者能读其中任意一个就能看到它，所以给一个已知事实再加一个受限来源，永远不会让它消失。

## 如何运作

### 为受众编写一个单元

页面编译器构建页面、流程或主题摘要时，会把候选陈述分成两组：单元的受众能读的，和不能读的。它只用第一组来写。第二组中的每条陈述属于以下之一：

- **已放行。** 它所在空间的维护人已经把它放行给这个受众（见下文“放行”）。它于是像其他陈述一样被使用，带着自己的敏感标签。
- **多余。** 受众已经能读到这条陈述的另一个依据，或者它没有给单元增加任何内容。直接去掉，不留痕迹。
- **省略。** 以上都不是。编译器检查省略它是否会改变意思（下一节）。

流程要么完整、要么不发布：只有受众能读到（或已被放行）每一步，流程才会发布。读者永远拿不到少了一步的流程。

### 省略检查

省略一个输入会改变意思，是指这个输入：

- 对单元用到的某个事实槽给出了不同的值（受众看不到的冲突），
- 是取代单元所说内容的更新版本，
- 给它加上了条件或例外，或者
- 论述了单元某个观点的另一面。

前三种无需模型，从知识模型（事实槽、取代关系、限定条件）就能发现。最后一种需要一次模型检查（`page_compiler.check_omission`，原型里有确定性的模拟实现）。不改变意思的省略，例如背景或额外细节，直接通过。

当省略确实改变意思时，单元会得到一条待办，和其他待办一样归入维护人的每周卡片，有三个选择：

1. **申请放行**被省略的陈述，由它们所在空间的维护人决定。
2. **改写，不在这一点上下结论**，例如“审批额度因部门而异，见财务空间”。编译器会给出建议措辞。
3. **带说明发布。** 这一小节显示“这一点上有部分材料在你无法打开的空间里，可联系财务空间维护人。”能读到这些材料的读者看到的是完整的小节。

待办发给单元的维护人；但被省略的材料是 `secret` 时例外：待办发给这份机密材料所在空间的维护人，只有这个人可以知道它的存在，并决定放行一条更正，或者保持单元不变。

### 放行

放行是把一条陈述开放给一个受众，而不是开放一个空间。它记录这条陈述、它来自的空间、目标受众、谁批准以及何时批准；这条记录成为受众能读的依据。放行的是陈述本身，证据引文默认不随之开放，除非放行时一并包含。陈述之后发生变化，或它所在的空间收窄受众，批准人会收到一条待办，决定保留还是撤回放行。这就是业务层与引擎契约中“跨越受众需要审批”的那次审批，改为按陈述进行，并有了名字。

### 回答

回答是为一位提问者、用这位提问者能读的内容写成的，所以从不被删减。返回之前，会用同样的省略检查，对照引擎所知、提问者读不到的内容。如果相关材料会改变回答，在 `internal` 和 `confidential` 级别，回答会说明它可能不完整，并指出可以问谁；对 `secret` 材料则什么都不说。回答从不在不完整时声称自己完整。

### 按读者的安全网

每次读取仍会按读者检查，但它是一道保证，而不是塑造单元的方式。它只作用于完整的条目：一篇文档、一个块、列表中的一条陈述、表格中的一行、一条搜索结果。它从不去掉行文中间的文字。如果检查不得不去掉段落中的一部分，例如在编译和阅读之间受众发生了变化，单元会按这位读者的可读空间集合重新编译，并对共享同一集合的所有人缓存。

### 文档

一篇文档要么整体可见，要么整体不可见，和它在原应用里一样。当文档的某一部分敏感标签更高（例如一份机密附录）时，这部分是一个独立的单元：没有相应许可级别的读者会看到一行“此部分受限”，而不是一篇悄悄缺了一块的文档。

## 滥用与意外

| 有人…… | 结果 |
| --- | --- |
| 把一个无关紧要但权限严格的备注关联到一个被广泛阅读的主题上 | 什么都不会消失。这条备注不用于更广的受众，主题维护人能在单元的“未使用输入”列表里看到它 |
| 在共享页面里引用一份机密文档 | 它不会被使用，也不留痕迹。如果它与页面矛盾，机密空间的维护人会收到待办 |
| 提高一个被广泛使用的来源的敏感标签，或收窄一个空间 | 这是有权限的变更，所以会生效。保存之前，操作人会看到它影响多少单元和读者。受影响的单元会重新编译，意思发生变化的会收到省略检查待办。整个过程留有审计记录 |
| 给一个公开事实加一个受限的副本 | 这个事实通过它的公开依据保持可见 |

## 验收测试

| 用例 | 预期 |
| --- | --- |
| 一个面向全员的页面，用到一份反对某项制度变更的公开文档，和一份只有财务能读、支持这项变更的备忘录 | 省略检查触发。页面维护人收到一条待办。页面绝不会在没有说明的情况下只呈现一面 |
| 一条无关紧要的受限备注被关联到一个有 300 位读者的主题 | 对任何人，都没有单元、陈述或小节消失 |
| 一个事实同时出现在一份公开文档和一份受限文档里 | 每位能读公开文档的读者都能看到这个事实 |
| 由销售价格和财务成本算出的毛利，本会出现在一个面向全员的页面上 | 除非财务放行，否则不使用。页面上的其他内容不变 |
| 一份机密文档与一个共享页面矛盾 | 共享页面上没有任何相关痕迹。机密空间的维护人收到待办 |
| 一位读者提问，而在提问者无法阅读的空间里答案不同（confidential） | 回答说明可能不完整，并指出可以问谁，但不给出另一个值 |
| 在编译和阅读之间受众收窄 | 读者拿到的是按其可读空间编译的页面，而不是缺了词的段落 |
| 一篇文档带有机密附录 | 没有相应许可级别的读者看到这篇文档，附录的位置有一行“此部分受限” |

## 契约变化

都是新增，流程见 [docs/contracts.md](../../contracts.md)。

- `PageSpec` 的块新增可选的 `omissions[] { reason, ask_space_id }`，渲染为给读者的说明。
- 新增 `Release { statement_id, from_space_id, to_space_id, include_quote, approved_by, approved_at }` 记录，可以作为依据。
- `Answer` 新增可选的 `incomplete { ask_space_ids }`。
- 每个汇编单元保存它未使用的输入及原因（`not_readable`、`secret`、`redundant`），供维护人查看。
- 待办类型 `omission_review`（collaboration）和模型任务 `page_compiler.check_omission`。

## 需要确认的取舍

- **读者会知道受限材料的存在，但从不知道它的内容。** 在 `internal` 和 `confidential` 级别，一条说明会告诉读者有相关内容在其无法打开的空间里，以及可以问谁。连这一点都隐藏，就会重新带来悄无声息的空缺，而对一个以正确为承诺的知识库来说，那更糟。Confluence、Notion 和 SharePoint 也显示类似的占位说明。在 `secret` 级别，什么都不透露。
- **面向广泛受众的页面，在维护人放行陈述之前可能说得少一些。** 维护人能看到省略了什么、为什么省略，所以能补上重要的空缺。
- **维护人的工作会增加，但有上限。** 只有意思发生变化时才产生省略检查待办，并且它们共用每周卡片的预算。
