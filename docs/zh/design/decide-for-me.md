# 替我决定：让助手代为决定

状态：已采纳，2026-11-05；已在 MVP 的第 4 片为待办箱构建。

## 结论

- **产品里每个要人做的决定都可以交给助手，而决定仍然属于这个人。** 助手以本人的权限、以本人的名义决定，给出理由和它读过的段落，每个决定都可以撤销。
- **三种委托方式：** 这些（一个操作处理整批、整张卡片或整个队列，其余留下）；这一个（建议已经选好，按回车接受）；这一类一直替我决定（长期委托，连续五次接受同一类建议后才提出，从不在未询问时打开）。
- **有些决定只准备、从不替你做：** 谁能读或使用知识、无法撤销的事，以及钱。助手没有把握、人与人意见不同，或者空间维护人把这一类留给人的时候，也会把决定留给本人。
- **目前没有模型任务。** 提出问题的组件附上自己的建议，助手按规则决定，用语言包写出理由（[引擎需要什么](#引擎需要什么)）。每类决定的把握门槛，以及会签的每一票是否都能委托，还没定。

## 原则

产品在任何地方请一个人做决定，这个人都可以让助手替他决定。决定仍然是他的。助手用这个人的权限、以他的名义决定，给出理由，这个人可以撤销。仍然是人在决定；人还可以决定自己亲自决定多少。

这条原则把“助手提议，人来决定”改成“每个决定都有一个人，他可以让助手替他决定”（[界面原则](ui-principles.md)第 5 条）。

它是每个决定点都有的性质，不是某个界面的功能。新界面只要请人做决定，就同样带上“替我决定”，规则也相同。

## 适用范围

| 决定 | 现在由谁决定 | 助手可以替他决定什么 |
| --- | --- | --- |
| 待复核 | 主题维护人 | 确认仍然成立的内容，把变了的标为已过时 |
| 冲突 | 主题维护人；投票分歧或超过截止日期后由空间维护人 | 选一个值，或者两个都保留并写明各自的范围 |
| 会签投票 | 每位投票人 | 这位投票人自己的一票 |
| 发布申请 | 审批人 | 批准、请求修改或拒绝 |
| 批量变更审阅 | 主题或空间维护人 | 按建议处理，或把主题交回各自的维护人 |
| 主题变更 | 主题或空间维护人 | 确认或保留提议的拆分、移动或新主题 |
| 未归类的陈述 | 主题维护人 | 归入建议的主题 |
| 备注 | 主题维护人 | 标为已读 |
| 原文已删除 | 主题或空间维护人 | 保留、指向替代文档，或停用 |
| 交接 | 空间维护人 | 接受建议的新维护人 |

有些决定**从不替你做**。在这些地方“替我决定”仍然可用，但只做准备：助手选好一个选项并说明理由，由本人按一下确认。包括：

- **谁能读或使用知识。** 谁能读一个空间、成员及其角色、使用知识的应用、授权页，以及来源权限收紧。
- **无法撤销的事。** 清除个人空间、删除数据，以及任何发到企业以外的内容。
- **钱。** 套餐、席位和用量上限。

## 三种委托方式

1. **这些。** 待办箱、队列或批量变更审阅顶部的概述，以及每张待办卡片，都有一个操作，把助手可以决定的一次处理完，其余留在原处，所以一张卡片可能停在“已决定 14 项 · 留给你 3 项”。“替我决定”主要出现在这里。
2. **这一个。** 单个决定上，助手的选择已经预先选好，标着“建议”并附理由；按回车就是接受。`d` 键、⌘K 和命令 `inspiration decide --for-me <item>` 不用打开就能决定一项。不会在每一项上都放一个“替我决定”按钮。
3. **这一类一直替我决定。** “以后这类都替我决定”会建立一条长期委托：一类决定、一个范围（空间、领域或主题），需要时再加一个条件，比如“供应商领域里的复核，只要来源只改了措辞”。长期委托列在待办箱的“一直替我决定”里，每条都可以暂停。某人连续五次接受助手对同一类决定的建议后，助手会问要不要以后都替他决定；不经询问从不自动开启。

## 助手怎么决定

- **只用这个人的权限。** 这个人看不到、改不了的，助手也看不到、改不了。
- **按细心的人会用的顺序。** 先看空间的规则（来自“设为规则”），再看这个人在同一范围里以前的决定，然后看来源的权威性和日期。文档数量只作参考，和其他地方一样。
- **每次都给理由。** 每个决定都附一两句理由和它读过的段落，让人几秒钟就能核对。

## 什么时候留给本人

遇到下面的情况，助手把决定留给本人，附上它的建议和一句原因：

- **没有把握。** 证据势均力敌，或者它的把握低于这类决定的门槛。
- **人与人意见不同。** 同一件事里已经有人做了不同的决定，或者有人留了未解决的评论。助手从不压过一个人：会签里它只投它所代表的那个人的一票；两个人的投票出现分歧时，它只为空间维护人准备决定。
- **空间维护人留给人来做。** 空间维护人可以把某类决定标为“只由人决定”，比如关于价格的冲突。
- **属于从不替你做的决定**，见上文。

留给本人的决定留在原处、顺序不变，标着“留给你”和原因。

## 记录与撤销

- **记录写明是谁、怎么做的。** 代为决定的决定和其他决定一样记录，决定人是本人，并注明“由助手代为决定”以及委托方式：这一个、这些，或某条长期委托。记录保留理由、读过的段落、模型任务和提示词版本。追溯、历史和审计日志都这样显示。
- **读者看不出区别。** 代为决定的决定就是决定。读者照常只看到结果。
- **随时可以撤销。** 在决定本身、它的记录或待办箱里都能撤销。撤销会恢复之前的状态，并把这一项重新交给本人。知识从不删除，所以撤销是一个恢复旧状态的新决定。撤销一次已批准的发布申请，会停用已发布的内容，申请回到审核中。
- **撤销会让助手学习。** 如果一个人撤销了助手最近十个同类决定中的两个，这一类的长期委托会暂停，先问本人再继续。
- **每周汇总。** 待办箱里有“已替你决定”视图：本周助手决定了什么、留下了什么、本人撤销了什么。它不需要操作，也不占每周卡片的额度。

## 谁来控制

- **每个人**控制自己的委托。
- **空间维护人**能看到空间里的长期委托，可以把某类决定标为“只由人决定”。会签时，由空间的审批设置决定投票能否委托；默认可以。
- **超级管理员**可以为整个企业关闭“替我决定”，比如在审计期间；在用量里能看到有多少决定是委托的，看不到它们的内容。
- **代为决定是模型工作**，计入该成员的用量。

## 引擎需要什么

下面这条规则随 MVP 的采纳而改变（[待决问题 9](../decisions.md#待决问题)）。其余是第 4 片要构建的内容。

- **规则。** `AGENTS.md` 规定内置智能体只读取或提议，智能体做的任何事都要有人批准才能改变知识。总览里的需求 AG-4 规定自行运行的智能体只读取或提议，成员的明确请求就是对其权限内修改的批准。委托不改变智能体一侧：助手仍然只提议。变的是批准。按下“替我决定”就是明确请求，已经符合 AG-4。长期委托是提前做出的请求，有范围、可撤回，所以 AG-4 补了一句，2026-11-05 已同意：“成员自己建立、可以暂停的长期委托，也算该成员在其权限内的批准”。
- **谁负责。** 协作组件：待办、待办箱以及处理待办都归它管。委托是成员对自己待办的一项设置。
- **契约，全部是新增**（`collab.yaml`、`api.yaml`）。`TodoDecision` 记录关闭时的待办、所选的处理方式及其文字、理由、读过的段落、怎么提出的（`assistant_once`、`assistant_batch` 或 `delegation`）、以谁的名义、什么时候，以及什么时候被撤销。待办箱里的待办上，`TodoSuggestion` 是助手会选的处理方式，`TodoLeft` 是它把待办留给本人的原因。`Delegation` 在 MVP 里每个成员一份：状态（`unset`、`on`、`paused`）、它决定的种类（`review_due`、`stale`、`conflict`、`note`），以及是谁暂停的。本人自己的处理照旧记在待办上。
- **第 4 片没有模型任务。** 提出问题的组件已经权衡过助手据以决定的证据：治理组件按权威和日期提出一个值，时效组件知道文档自上次复核以来是否改过。它们在提出待办时附上自己的建议，以及是否有把握。助手据此和[什么时候留给本人](#什么时候留给本人)里的规则做决定，并用语言包以成员的语言写出理由。所以决定一张卡片只是查找，立即就能回答。只有当这些规则把太多决定留给人时，才增加模型任务（`collaboration.decide_todo`，带替身）。
- **API。** 下面这些都以成员的身份执行，写操作需要 `knowledge.propose`。
  - `POST /v0/inbox/decide` 接收 `DecideTodos`（一张卡片或几条待办），回答 `Decided`，其中包括做出的决定和留下的待办。
  - `POST /v0/decisions/:decision/undo` 回答重新打开的 `InboxTodo`；如果这个决定已经撤销过，或者被后来的决定取代，回答 409。
  - `GET /v0/inbox/decided` 回答 `DecidedWeek`。
  - `GET /v0/delegation` 回答成员的 `Delegation`，`PUT /v0/delegation` 用 `PutDelegation` 开启或暂停它。
- **评测。** 在助手提出“以后这类都替你决定”之前，先衡量它在这类决定上和人的决定有多一致。在模拟原型里，这些数字衡量的是流程，不是质量。

## 还没定

- 每类决定的把握门槛，以及用真实模型时怎么衡量。
- 会签的每一票是否都可以委托，以至于一个冲突可以在没有任何人投票的情况下决定。提议：可以，除非空间维护人把冲突标为“只由人决定”。
