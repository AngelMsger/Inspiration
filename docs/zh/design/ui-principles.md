# Inspiration 界面：交互原则与视觉设计

状态：已采纳的设计，2026-10-24。界面画在产品负责人的设计画布上，目前还没有生产界面代码。配套文档：[规模化的陈述](statements-at-scale.md)，说明陈述如何组织和复核。本文是英文版 [docs/design/ui-principles.md](../../design/ui-principles.md) 的中文副本，两者不一致时以英文版为准。

## 界面服务谁

| 角色 | 做什么 |
| --- | --- |
| 成员 | 企业里的一个人。阅读知识页、提问、评论，并在“我的空间”里保存自己的资料。大多数成员在大部分时间里只是读者 |
| 空间、主题、页面或流程维护人 | 为一个空间、主题、页面或流程指定。审批发布到那里的内容，保持其中的陈述最新，确认它们的归属，裁决其中的冲突，并把陈述放行给更广的受众。空间维护人还决定谁能阅读这个空间以及它的治理级别，接手没有维护人的主题，批量处理积压，并在投票分歧或超时时做决定 |
| 超级管理员 | 管理整个企业：成员、与来源应用的连接、企业设置、审计和用量。创建空间并指定其维护人，但从不决定知识说什么。永远看不到“我的空间”，也看不到任何人问了什么、读了什么 |
| 一个人使用的人 | 拥有个人知识库，从不看到企业、空间、成员或发布 |

界面上只有这几个角色。产品内部的权限更细，以后拆分角色时，这些界面不需要大改。

这些人工作的地方：

- **企业**是一家公司的共享区域，例如恒远机械。
- **空间**是企业中的一个区域，例如采购部。由它的维护人决定谁能阅读；超级管理员只能在安全事件中收窄。
- **我的空间**是成员在企业内的私有区域。其他任何人都看不到里面的内容，超级管理员也不例外。
- **个人知识库**是一个人在和别人一起使用之前拥有的东西。邀请别人或新建企业之后，企业切换器和“我的空间”才会出现。

## 交互原则

1. **阅读优先，治理按需出现。** 页面打开时是一份干净的文档。维护人、投票和规则只在有人询问或操作时才出现。知识模型本身（陈述、计数、来龙去脉）从不出现在阅读界面上；维护人在追溯视图里看它。
2. **每条陈述都显示它从哪里来、有多新。** 引用点一下就到来源段落，状态总是用文字写明（有效、待复核、已过时、有争议），绝不只靠颜色。
3. **始终显示你在哪个空间、谁能读。** 空间切换器放在顶栏，每个空间都说明由其维护人设定的可见范围，并带上人数，例如“采购部全体 18 人”。
4. **助手提议，人来决定。** 助手起草选项、提出冲突、回答问题，但投票、审批或发布的是一个具名的人。
5. **绝不交出凭据，并让扩大范围看得见。** 个人连接保持个人所有。发布时显示谁将能阅读，当部分读者无法打开原文时给出提示，但不阻止发布。
6. **冲突总有维护人、截止日期、审批方式、截止后的决定人和记录。** 在此期间，读者看到的是最后一次核实过的值，标为有争议，除非维护人另有选择。
7. **一个待办箱。** 复核、投票、备注、重新连接请求和回复都进同一个地方，分组成卡片，按截止日期排序。
8. **默认安静。** 只有“已过时”和“有争议”标记会出现在行内。其他一切留在页边或侧栏。
9. **键盘、命令和 CLI 对等。** 每个操作都有快捷键、命令面板条目和对应的 CLI 命令。
10. **从第一天起就是三种语言。** 每个界面都提供英文、中文和日文。字体、行高和行长按语言分别调整，布局为最长的标签留出空间。
11. **用历史建立信任。** 每个值都能回答“为什么是这个值？”：谁核实的、何时核实、由哪项决定或规则设定。

## 视觉系统

整体风格是“墨与纸”：暖色纸张底色、衬线阅读字体、唯一的靛蓝色用于操作，以及带文字的小状态标记。默认是阅读密度。另外加入两个面向维护人的工具，而不改变这种气质：命令面板，以及带检查器侧栏的紧凑模式。首页还有一个提问栏。

| 设计变量 | 值 | 用途 |
| --- | --- | --- |
| paper | #EFEEE9 | 应用底色 |
| page | #FBFAF7 | 文档表面 |
| ink | #1C1E23 | 正文 |
| muted | #545964 | 次要文字 |
| faint | #636874 | 第三级文字；在纸张底色上对比度不低于 4.5:1 |
| rule | #DCDAD2 | 分隔线和边框 |
| indigo | #2E3F8F（悬停 #1F2C6B，浅色 #E7E9F4） | 操作、链接、选中 |
| fresh | #E3EFE8 底上的 #2D6A4F | “有效”状态标记 |
| due | #F5EBD6 底上的 #8A5A00 | “待复核”状态标记 |
| disputed | #F6E2DC 底上的 #A3341F | “有争议”状态标记 |

- **字体。** 每种语言各有一对阅读字体和界面字体：英文用 Newsreader 和 Instrument Sans，中文用 Noto Serif SC 和 Noto Sans SC，日文用 Noto Serif JP 和 Noto Sans JP。代码和 CLI 命令用 Geist Mono。
- **密度。** 阅读密度处处适用，也是触屏上唯一的密度。紧凑密度（13 px 文字，右侧检查器）供桌面端的维护人和超级管理员使用，用 ⌘ .（Command 加句号）切换。
- **命令面板。** 每个界面都可用 ⌘K 打开。每一行显示操作、它的快捷键和对应的 CLI 命令。
- **提问栏。** 只在首页，墨色边框、衬线输入框。其他地方由顶栏搜索承担。
- **深色主题。** 深色设计变量已经存在，所有文字对比度不低于 5.7:1，但深色主题不在第一个版本中。

## 布局

- **顶栏**：企业和空间切换器（一个人使用时隐藏）、提问或搜索、账户菜单（包括界面语言）。
- **左侧**：知识树（空间、主题、页面）和来源树（已连接的应用及其文件夹），每个来源应用有自己的图标。
- **中间**：文档本身。来源有原文视图（按原样）和批注视图（行内标出已过时和有争议的行，其他批注在页边），外加一个“已入知识”标签，可跳到使用它的页面。知识页在行内引用它的来源。
- **右侧栏**：评论、来源、相关、历史。点击引用会在页面旁边打开来源。
- **选中文字后的菜单**：评论、高亮、这已过时、提议更正、就此提问。

## 知识如何呈现

读者永远看不到页面背后的结构。知识页、流程或主题页读起来就是一份普通文档：正文、小小的引用编号，以及仅有的“有争议”和“已过时”标记。点击编号会显示来源段落和一句状态说明。

页面背后，知识分为几层：

- **来源**保持原样，放在来源树里。不会逐份文档复制或清洗。
- **段落**是引擎从来源中切出的片段。之后的每一层都指回它们。
- **陈述**是最小的受治理单元：一个事实，带着它的状态、维护人、生效日期和它背后的段落。复核、争议和规则都作用在陈述上。关于同一事实的陈述共用一个事实槽。
- **知识形态**只由陈述构成：知识页、流程，以及关于城市、供应商或角色等对象的卡片。一条陈述可以出现在多种形态里，所以只需治理一次。
- **知识树**把所有内容归在主题下。每个主题有一位维护人，没有时由空间维护人接手；每个空间始终有维护人。新来源在主题维护人确认助手的建议后归入该主题。

每个来源还有一个治理级别：严格级别的来源完整抽取并接受复核，宽松级别的来源只在被使用时抽取，仅检索级别的来源只用于搜索。[规模化的陈述](statements-at-scale.md)介绍了各级别和实测数量。

陈述、计数、来源和来龙去脉都在**追溯视图**里，由维护人有意打开：从页面的 ⋯ 菜单、⌘K 或 CLI，在紧凑模式下。页面文字由助手根据陈述写成，所以编辑文字就是对背后的陈述提出修改；争议结束时，使用这条陈述的每个页面、流程和卡片一起更新。

状态由引擎的新鲜度状态映射而来。有效和正在变旧不显示任何东西。过时和有风险显示“待复核”，而且只在引用浮窗和追溯视图里。被取代显示“已过时”，有争议显示“有争议”；只有这两个标记出现在行内。在原型中，一年不复核后约五分之一的文档会过时，所以行内过时标记会出现在五分之一的页面上。

## 界面中的权限

- **谁能读由空间决定，从不由来源决定。** 界面显示由空间维护人设定的可见范围，从不显示根据来源权限推算的人数。
- **我的空间是私有的。** 成员自己的资料在发布之前一直是私有的。超级管理员打不开。
- **发布是把知识移进一个空间。** 对每个来源，发布界面只问一个问题：它如何保持更新。选项是通过企业连接保持更新（默认）、通过我的连接保持更新（需本人同意），或发布带复核日期的快照。没有在线连接的文件只能作为快照发布。
- **来源权限只作提示。** “部分读者无法打开原文”出现在发布界面，从不阻止发布。发布后，当某个来源自身的权限收窄时，空间维护人会收到一条“来源权限收紧”待办，可选择保持可见、隐藏这些知识，或查看受影响的条目。
- **超级管理员看得到流程和用量，看不到内容。** 发布队列显示进度和检查结果；用量按成员和工作类型显示数量，从不显示问题或页面。超级管理员可以改审批人；接手的人同样只能看到这次申请里的条目，变更会记入审计日志。
- **一个人使用时隐藏企业。** 一个人使用时完全看不到企业、空间、成员或发布。

## 待办与复核

一位维护人的待办箱每周只有几张卡片。同一维护人、同一主题、同一周的待办共用一张最多 20 条的卡片，每位维护人每周最多 10 张卡片；更紧急的工作从不等待。冲突卡片里带着重复该争议值的文档的复核（“用在 4 处，决定后一起更新”）。备注（只有宽松级别的文档给出不同值的情况）放在每周备注卡片上，不占预算，一个操作即可确认。企业接入来源当天就已到期的复核，成为空间维护人的首次复核专项卡片，在紧凑模式下处理。实测数量见[规模化的陈述](statements-at-scale.md)。

## 国际化

Inspiration 是国际化产品。英文、简体中文和日文从第一个版本起就平等对待。画布用中文讲演示故事，但中文只是三种语言之一，不是默认语言。

- **界面跟随个人，内容保持自己的语言。** 每个人在账户菜单里选择界面语言。它属于账户本身，所以在每个企业都一样，初始值在注册时取自浏览器。企业另有一个默认语言，用于发给很多人的消息。来源保持原来的语言，从不被悄悄翻译。
- **每个空间有一种内容语言。** 由空间维护人设定，助手用它撰写该空间的知识页。日文成员阅读中文空间时，看到的是日文的菜单、按钮和状态，包围着中文的页面。
- **回答跟随提问的人。** 助手用提问者的界面语言回答，引用的段落保持原文语言。引用浮窗可以按需显示译文，标明是机器翻译，点一下就回到原文。
- **一份词表，三种语言。** 每个产品术语都有英文、中文和日文形式（见“词表”）。状态、按钮和空状态文案都从词表出发书写，从不临时翻译。
- **按文字体系选字体。** 中文和日文共用许多汉字，但部分字形不同，所以每个块都带语言标记，中文页面里引用的日文段落仍用日文字形显示。中文和日文正文行高约 1.75，不加字间距；日文遵守其换行规则：行首不出现右侧标点或小假名。
- **为最长的标签留出空间。** 英文标签约是中文的 1.5 到 2 倍宽，日文介于两者之间。按钮、标签页、表头和小标签按内容确定尺寸，放不下就换行，不截断。紧凑模式用英文检查，因为它最长。测试中运行一个字符串被拉长的伪语言。
- **格式来自语言区域规则。** 日期、大数字、货币和复数形式都按各语言的规则，例如英文的“Oct 24, 2026”对应中文和日文的写法，“137.8k”对应以“万”为单位的写法。句子从不用片段拼接，因为三种语言的语序不同。
- **姓名和排序。** 姓名按本人使用的顺序和文字显示，问候语不假设有“名”。列表按各语言的排序规则排列。
- **输入法。** 中文和日文通过输入法输入，文字先组字再上屏。组字时按回车绝不提交提问栏、发送评论或执行命令面板里的命令；文本框有焦点时，单键快捷键关闭。
- **跨语言的搜索和陈述。** 检索在建索引前先对中文和日文分词。事实槽应按规范化的主语和谓词建键，而不是按字面用词，这样中文制度和日文纪要里说的同一个住宿上限会落在同一个事实槽里。这两条属于引擎。

## 界面用词

界面上从不出现“租户”、内部 ID 或用户名。审批方式有单人审批、或签、会签和至少 n 人。发布申请依次经过草稿、审核中、已发布和已停用。

## 决定

于 2026-10-23 和 2026-10-24 采纳：

- 以“墨与纸”系统为基础，加入命令面板、紧凑模式和检查器，以及首页的提问栏。
- “陈述”是读者看到的一条知识的叫法。
- 知识视图：原文、批注和知识三个视图，以及来源树和知识树。
- 助手在三种语言里都就叫“助手”，没有自己的名字和标志。
- 第一个版本不做深色主题；它的设计变量保留在设计系统里。
- 最先做的手机界面是阅读、会签和待办箱。
- 词表中的中文用词。

于 2026-10-26 采纳：

- 界面上只有三个角色：成员、维护人和超级管理员。维护人总是带上范围（空间维护人、主题维护人、页面维护人、流程维护人），因为单说“维护人”容易产生歧义。
- 同一天稍后提议、等待产品负责人确认：超级管理员管理企业，维护人维护知识（超级管理员创建空间并指定维护人，但从不决定知识说什么、谁能读一个空间）；中文里这个角色改称“维护人”，不再用“负责人”。见[总览](../overview.md)第 4 节。
- 中文里企业叫“企业”，治理级别叫“严格”“宽松”“仅检索”。英文与之对应叫 Company，日文叫“企業”。
