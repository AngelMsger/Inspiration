# Drive 与知识文件

状态：提议中，2026-11-13；产品负责人已确定 Drive 方向，下文的文件类型、知识颗粒度与交互仍是提案，当前应用已有上传及独立的文档、知识视图。

## 结论

**Drive 是整个产品组织和使用内容的一层。** 文档树以文件的方式管理内容；知识可以按合适的颗粒度具象化为有名称、可复用的文件，原始上传材料也可以与它放在一起。查找、阅读、提问、整理和维护内容应当形成连贯的工作流程。

产品负责人的[决定](../decisions.md)明确了 Drive 层和文件化文档管理。本文其余部分提出具体方案：

- 文件有稳定身份、存放位置和适合其类型的阅读方式。文件夹组织文件；来源、主题和保存的筛选提供找到同一内容的其他路径。
- 原始材料和整理后的知识可以放在同一个文件夹。类型帮助读者判断该打开哪一个、内容从哪里来、怎样更新。
- 知识文件对应一个有用的问题、流程或对象。陈述和证据仍是引擎中的共享对象，整理文件不会复制事实。
- 日常操作体现知识上的影响：文件用在哪里、更新影响什么、移动或移除意味着什么。

这里的 Drive 是产品概念，其最终界面名称、新知识域或新引擎组件均未定案。

## 仍需确定的选择

| 选择 | 建议起点 | 原因 |
| --- | --- | --- |
| 知识文件的默认颗粒度 | 聚焦一个问题的知识页；流程和对象卡片在相应阅读能力就绪后共用文件外壳 | 形成可独立阅读和分享的单位，避免每条陈述都变成文件 |
| 原始上传材料 | 一等文件，保留原始字节和可阅读的解析内容 | 解析失败或格式不支持时，用户的材料仍然存在 |
| 导航 | 每个空间内有 Drive，企业级入口汇总有权访问的空间 | 沿用空间作为责任和可见范围的边界 |
| 知识具象化 | 从选中的材料、主题或带引用的回答显式创建，助手建议标题、范围和位置 | 避免目录自动膨胀成大量细碎的生成文件 |
| 首次交付 | 先跑通上传到知识文件的完整流程，再增加高级集合和新卡片类型 | 先验证完整交互，再增加类型 |

这些选择供评审，不直接加入已采纳的 MVP 验收关卡。界面名称和日文用词仍待确定。

## 内容层级与身份

建议的组织关系是 `企业 → 空间 → 文件夹 → 文件`。个人知识库和“我的空间”在交付时使用同样的交互词汇，同时保留现有的独立知识域。企业级 Drive 只汇总成员有权访问的内容，不成为一个自动授予访问权的共享根目录。

每个文件有一个主位置和稳定链接。在同一空间重命名、移动，改变的是位置，文件身份、版本和引用保持有效。快捷方式在另一位置引用同一文件，无须复制内容。主题表达知识含义和维护责任；文件夹表达人的整理位置，两者不悄悄互相改写。

文档树成为文件层级视图。知识树继续按主题呈现文件背后的知识，包括尚未具象化为文件的知识。它们是进入相关对象的不同路径，不需要分别维护两套副本。

原始来源的层级也可以作为来源视图浏览。本地整理不会重命名、移动或删除飞书、Confluence 中的内容。上游移动会更新显示的来源路径，成员明确安排的本地位置保持不变。

## 文件代表什么

| 类型 | 打开后看到 | 内容和更新方式 |
| --- | --- | --- |
| 上传材料 | 原文预览，在能力可用时提供批注和知识视图 | 原始字节、解析内容及版本历史；替换通过明确的上传新版本操作完成 |
| 连接文档 | 导入的原文、上游链接和同步状态 | 同一来源文档在产品内的表示；刷新跟随来源连接，本地整理独立于来源位置 |
| 知识文件 | 带引用的知识页、流程或对象卡片 | 在受治理陈述之上保存的范围和表达形式，有自己的修订记录和具名负责人 |
| 快捷方式 | 目标内容，以及返回入口的路径 | 引用同一文件，不增加证据、权威性、可见范围或内容版本 |

文件夹和保存的集合是容器与视图，不是证据。保存的集合重新执行筛选，例如“需要复核的差旅知识”；成员变化不移动文件。一个主题不会自动同时成为文件夹和知识文件。

统一文件外壳提供名称、位置、类型、负责人、相关日期、可见范围和历史。操作由类型决定：上传材料可上传新版本；连接文档可刷新或打开上游；知识可查看变化或提出修订。有文件图标不等于所有类型都可直接编辑。下载原始文件与导出知识快照是不同操作；导出内容记录修订、日期和引用，离开 Inspiration 后不再自动更新。

## 知识颗粒度与具象化

边界应当是一个人能够独立命名、阅读、维护和复用的单位。“差旅报销”可以是一页知识，“提交报销申请”可以是一个流程，“深圳住宿规定”可以是更小的参考卡片。某个住宿限额通常留在这些文件内部，整个财务空间通常是一组文件。

只有在成员明确需要独立复用某条事实时，才将单条陈述具象化，并保留条件和证据。如果一个文件反复需要无关的章节、负责人或复核周期，应考虑拆分；如果几个碎片总被一起打开，应考虑合并。文件大小由阅读和维护需要决定，不等同于抽取的文本块大小。

“创建知识文件”可从选中的文件或段落、主题、带引用的回答开始。创建面板展示：

1. 建议名称和保存位置，以及目标位置的可见范围。
2. 覆盖的问题或主题、选中的来源材料，以及排除的内容。
3. 带引用的预览，标出未决冲突或缺少支持的结论。
4. 更新方式：跟随保存的范围，或保留带日期、复核日期的快照。

选择一组文件时，跟随这些文件的稳定身份及后续版本；选择主题时，随着主题变化可以纳入相关的新证据；快照不会纳入。创建面板明确说明这一差异。来源发现、治理和发布沿用现有规则；“跟随更新”不代表批准有争议的事实，也不扩大受众。

保存后形成文件身份、范围和第一版内容。后续整理产生新修订，保留人工覆盖和每版使用的证据。快照固定创建时有依据的陈述和来源版本，并不因此获得向其他受众披露的权限。

回答带引用，并不代表其中每句话都能成为已验证的知识。保存回答时保留有依据的内容，缺乏支持的部分明确保持为草稿或提案。知识文件不能重新被当作同一批陈述的独立证据导入。翻译、快捷方式、导出件或表达形式的副本，都不增加支持某个事实的来源数量。

## Drive 界面

Drive 遵循[界面设计哲学](ui-philosophy.md)：沿用企业顶栏、空间导航、主区域和选择面板，属于日常阅读与工作区域。空间维护、管理后台和账户保留各自的位置。

空间内，主区域以面包屑、当前位置搜索和当前任务的主要操作开头。最近使用、收藏提供捷径；全部文件、原始材料和知识是同一清单的不同视图。文件夹可以混放类型。文件行显示类型、标题、相关更新日期，以及值得注意的异常；紧凑视图可增加来源、负责人等列。文件夹可根据真实数量简述发生了什么变化、哪些需要处理。

选中一行，在面板预览，无须离开列表；打开则进入对应阅读器。面板按类型提供内容、来源、使用位置和活动。知识文件可以回到证据，来源可以查看使用它的知识。返回时恢复筛选、滚动位置和选择。引用仍然打开准确的段落及版本，而非只打开文件的最新版。

左侧栏定位空间和文件夹。搜索、筛选、排序和视图控制放在主区域上方。无需常驻聊天侧栏：“针对这些内容提问”明确采用选中的文件、多选内容或文件夹作为范围，就地打开带引用的回答；范围内证据不足时必须说明。

## 日常交互

| 任务 | 交互与反馈 |
| --- | --- |
| 上传文件或文件夹 | 拖到明确高亮的目标位置，或使用上传按钮。保留相对目录。分别展示传输、解析、索引和读取，支持逐文件重试，离开页面后仍可查看结果 |
| 处理重复 | 说明是相同内容、可能的新版本，还是仅名称相同。提供跳过、上传新版本、保留两份；不能仅凭同名就静默覆盖 |
| 浏览和预览 | 点击或方向键选择，Enter 打开，Escape 关闭预览。保留原生链接以便在新标签页打开，阅读返回后恢复位置 |
| 整理 | 菜单和键盘均可新建文件夹、重命名、移动、收藏、创建快捷方式。拖拽高亮目标并在释放前说明操作，拖拽不能是唯一途径 |
| 处理多选 | 复选框、范围选择和键盘选择唤出批量工具栏。显示选中数量，并区分当前页与全部匹配结果。明确部分失败，仅重试失败项目 |
| 创建知识 | 从选择打开前述范围与预览面板。保存后进入知识文件，可回到输入材料；离开创建面板保留草稿 |
| 理解更新 | “来源已变化”打开差异和受影响知识。区分同步中、待复核，以及读者当前看到的已发布版本 |
| 就地提问 | 问题旁显示范围。可将有依据的结果保存为知识文件，并保留引用 |
| 助手整理 | 展示建议的名称、目标位置及理由。按成员请求在其权限内执行，记录活动并可撤销；自主建议不会移动文件 |
| 移除和恢复 | 区分删除快捷方式、将文件移入回收站、停用知识。有实质影响的移除先展示依赖；恢复优先使用原位置，位置不可用时选择目的地 |

撤销明确说明逆转哪项操作。回退内容创建新修订，不抹掉中间历史，也不静默覆盖其他成员的新工作。并发修改和移动按成员看到的修订检查；过时操作刷新相关项目并说明发生了什么变化。

## 交互必须保留的边界

**可见范围沿用现有知识域和空间规则。** 快捷方式、集合成员、搜索摘要、依赖计数和预览面板都不能暴露无权访问的目标，快捷方式不授予访问权。来源应用的访问权与 Inspiration 的访问权仍然分开；Drive 不重新引入所有来源 ACL 取交集的规则。[汇编知识权限](compiled-knowledge-permissions.md)中未决的取舍仍待确定。

**移动可能不只改变位置。** 同一空间的普通移动保持身份和引用；若目标位置改变继承的治理级别，执行前展示实际变化，以及由此带来的读取或复核工作，保留显式覆盖。共享内容跨空间移动经过适用的受众和敏感度检查。“我的空间”移入共享空间属于发布；拖拽进入相应流程，不绕过它。跨企业移动不在首次交付范围。

**移除文件不等于抹去事实。** 删除快捷方式只影响该入口。回收站将文件从普通浏览和搜索中移除，但保留版本及有权访问的证据链接。现有知识继续受治理，直到明确的停用决定关闭相关陈述；其他支持来源仍然有效。影响面板在适用时提供既有的保留快照、指定替代来源、停用选项。上游删除遵循[来源变化](source-changes.md)，包括成组复核。永久抹除与保留策略需要单独设计。

**存储、处理和知识状态分别表达。** “已上传”不等于已解析、可检索、已读取或已验证。不支持的文件仍可下载并说明原因；解析失败提供重试。解析成功的文件仍可能存在知识冲突。文件夹概览和筛选保留这些区别，无须在每行展示所有状态。

## 实现边界与迁移

现有起点包括[文档列表](../../../apps/web/src/documents.tsx)、[上传](../../../apps/web/src/upload.tsx)、[主题阅读](../../../apps/web/src/knowledge.tsx)、[路由](../../../apps/web/src/route.tsx)，以及[来源](../../../libs/contracts/schema/source.yaml)、[文档读取](../../../libs/contracts/schema/api.yaml)和[页面](../../../libs/contracts/schema/page.yaml)契约。当前文档按来源和路径组织，尚无支持独立文件位置及持久化知识文件的通用 Drive 清单。

实现首先区分来源身份、来源版本、本地文件位置、知识身份及表达修订。文件路径不能成为证据标识。为既有上传材料和连接文档建立映射，保留旧文档和引用链接，并在增加界面写操作前验证重命名、移动和上游重新同步。引入知识文件具象化时，现有主题导航继续有效。

文件元数据和位置与原始字节、证据、汇编内容分开持久化。所有列表和操作都经过既有 AuthZ 边界。模型工作仍在引擎中通过 ModelGateway 完成；业务后端传入成员上下文，网页不直接访问引擎。组件归属、增量 schema 和迁移机制需在实现前确定，本文没有据此批准新增模块。

## 首个切片与验收

建议首个切片跑通完整闭环：上传差旅材料到文件夹，预览并整理，创建一份带引用的知识页，跟进来源新版本，再回到受影响的知识。它包括真实持久化、稳定链接、重命名与移动、选择与预览、明确的更新及移除语义、可恢复的处理错误。高级集合、新对象卡片阅读器和跨空间发布界面可随底层能力继续交付。

以下场景用于评审交互，并在实现后验收：

1. 上传包含有效文档和不支持格式的文件夹。两者都可见，路径保留；只有符合条件的内容进入搜索或作为证据。重试不会重复成功项。
2. 从两份文档创建“差旅报销”。文件展示范围、负责人、更新模式、引用和当前状态；具象化不产生重复陈述或循环证据。
3. 重命名并移动来源，再次同步。来源只出现一次，并保留选定的本地位置。旧回答的引用、来源和知识之间的双向导航继续有效。
4. 上传改变住宿限额的新版本。旧版本仍可阅读；相关知识按实际情况展示待处理变化或新的受治理版本。人工固定的覆盖保留，有冲突时进入复核。
5. 将文件移入不同治理级别的文件夹。成员看到实际策略变化和影响。多选中只有部分项目有权限时，明确失败项目，不宣称全部成功。
6. 以只能访问一个空间的成员打开 Drive。搜索、计数、最近使用、快捷方式、预览和依赖面板都不暴露另一空间；发布使用已有审批流程。
7. 将被知识使用的来源移入回收站再恢复。普通浏览随之变化，有权限的历史引用仍可打开，知识不会被静默撤回。删除快捷方式不影响目标。
8. 在 3,000 份文档的空间和 50,000 份文档的大规模场景下浏览。按需加载目录，搜索分页，长列表虚拟化；保留选择，不因每次操作加载整棵树。在本地验证机器测量列表、搜索和预览的 p95 耗时，再确定性能目标。
9. 在英文、中文和日文中仅用键盘完成浏览、选择、重命名和移动。焦点可预期，屏幕阅读器播报操作结果，输入法组字时按 Enter 不会提交操作。

## 关于本文

写于 2026-11-13，依据产品负责人提出的方向：整个产品需要 Drive 层，文档树按文件管理，知识可按特定颗粒度成为特殊文件，原始上传材料也可以是文件。在既有“先文档后知识”的设计上，本文提出内容管理模型和具体交互。方向记录在[决定](../decisions.md)，细节采纳及交付顺序仍待确定。本文是英文版 [docs/design/drive.md](../../design/drive.md) 的中文副本，两者不一致时以英文版为准。
