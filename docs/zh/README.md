# 文档

从[总览](overview.md)开始读；下表说明某个问题该去哪里找。这里的每篇文档都是 [docs/](../README.md) 中英文文档在相同路径下的中文副本；两者不一致时以英文版为准。每篇设计文档开头是一句话的状态，同时说明构建到了哪里，接着是结论；文档的历史放在末尾的“关于本文”里。本索引重复这一状态，`test/docs.test.ts` 检查英文版的两者是否一致。

| 状态 | 含义 |
| --- | --- |
| 已采纳 | 产品负责人已决定；按它构建 |
| 提议中 | 等待产品负责人决定 |
| 已取代 | 已被替换；只在其历史仍有价值时保留，并链接到替换它的文档 |
| 参考 | 描述已构建的部分 |

一篇文档被替换时，替换它的拉取请求要么删除它（git 历史会保留），要么把它标为已取代，并更新本索引（见 [AGENTS.md](../../AGENTS.md) 中的 “Keeping the repo small”）。

| 想了解 | 阅读 |
| --- | --- |
| 产品是什么、为谁而做、为什么 | [总览](overview.md)第一部分 |
| 现在在构建什么，暂时不做什么 | [MVP](design/mvp.md) |
| 已经决定了什么，还有什么待决 | [决定与待决问题](decisions.md) |
| 已经证明了什么，花了多少钱 | [验证知识核心](design/validation.md)的“现在的状况” |
| 系统怎样组成 | 总览的[架构概览](overview.md#9-架构概览)，然后是[架构](architecture.md) |
| 怎样构建、测试和运行 | [开发](development.md) |
| 某个方面为什么这样设计 | 下面对应的设计文档 |
