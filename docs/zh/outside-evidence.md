# 外部旁证

项目之外的研究，对照我们自己的结果来读，使引用它的主张只按它真实的分量引用。每一条先给结论，再写这项研究表明了什么、它与我们的主张有什么关系、它的局限，以及我们能用上什么。来源只链接，不复制。用来对照的结果见[验证知识核心](design/validation.md)。本文是 [docs/outside-evidence.md](../outside-evidence.md) 的中文副本；两者不一致时以英文版为准。

## 目前的结论

1. **目前只有一篇论文。它支持治理背后的机制，不支持我们领先的幅度，也不涉及成本。** Liu（2026）发现，在检索任务中，模型失败的原因是输入里有被问事实的竞争值，而不是输入太长。这正是在回答之前先处理过时和冲突的值应当有用的原因，也和我们领先的来源一致：在有变化或冲突的问题上比成熟 RAG 高 6.9 个百分点，在对照题上没有差别。论文没有测试带日期或来源的竞争值，没有 RAG 基线，也没有测成本、速度和治理本身的成本，所以我们的决定性测试仍是主要证据。
2. **论文和我们的运行都不支持"输入越小越容易答对"。** 原始长上下文读入整个话题（每个约 220,000 个 token），276 个问题答对 252 个，超过所有只读几千个 token 的方案。治理后输入小，是我们在成本和速度上的论点，这个论点要靠我们自己的测量。

## Length Is Cheap, Competition Is Not（Liu，2026）

Yinuo Liu，*Length Is Cheap, Competition Is Not: Attention Predicts Context Rot in Retrieval*，[arXiv:2611.04169](https://arxiv.org/abs/2611.04169)，2026-11-04 发布，作者一人，来自加州大学圣地亚哥分校；预印本，尚未经过同行评审。[代码](https://github.com/yliusci/length-is-cheap)和全部 126,473 次试验的逐条测量（[数据集](https://huggingface.co/datasets/yliusci/length-is-cheap)，MIT 许可证）都已公开。2026-11-05 通过 [Hugging Face 的论文页](https://huggingface.co/papers/2611.04169)读完全文，因为项目的云端会话访问不了 arxiv.org。

**结论：对"治理为什么能在冲突的事实上帮上忙"是中等强度的支持；对"能帮多少"、成本或速度、治理本身花多少，都没有支持。**

### 它表明了什么

任务是合成的查找（"The secret code of the river is 4821"，然后问"what is the secret code of the river?"），用五个 0.5B 到 3B 参数的开源模型，输入长度 512 到 32,768 个 token。每次比较都固定长度和证据的位置，只改变证据周围的内容。

- 中性文本几乎没有代价：准确率保持在 0.97 到 1.00；Qwen2.5-1.5B 到 32K 个 token 都如此，另外三个模型到 4K 个 token 如此（OLMo-2-1B 是例外）。
- 在相同位置换成与证据格式相同的陈述，在 8K 到 32K 个 token 时准确率降到 0.11 到 0.21。几乎全部损失都来自给被问的键另一个值的陈述：没有这种陈述时准确率 0.97 到 1.00；有一条时 0.25 到 0.52；每多一条竞争值，损失再增加。只是格式相同的陈述最多解释 0.3% 的损失。
- 模型留在证据上的注意力能预测损失：在 126,473 次试验中解释 35% 到 58% 的方差，而长度的对数只解释 2% 到 8%。存在一个阈值：在 Qwen2.5-1.5B 上，这个注意力降到约 0.35 之前损失接近零，之后急剧上升。
- 把填充内容从注意力中屏蔽而保留其位置（"仅长度就有害"这一说法所依据的做法），在检索中 32K 个 token 时损失 46 个百分点的准确率，而同样的填充内容保持可见时没有损失。
- 它的建议："deduplicating and resolving conflicting statements before they reach the model should matter more than shortening the context"（在陈述进入模型之前去重并解决冲突，应当比缩短上下文更重要），因为 "context engineering, not context length, is the lever"（起作用的是上下文工程，而不是上下文长度）。

### 与我们主张的关系

| 我们的主张 | 论文怎么说 | 我们自己的证据 |
| --- | --- | --- |
| 在有变化和冲突的事实上，治理后的回答更常答对 | 支持其机制：造成失败的是被问事实的竞争值，不是长度 | 276 个问题中 Inspiration 248 对成熟 RAG 234：在 204 个有变化或冲突的问题上高 6.9 个百分点，72 个对照题各 70。治理后的长上下文答对全部 27 个在别处公告的变更，原始长上下文 16 个。在共享盘测试集上，旧的 2,500 美元上限被当作现行值回答，是因为旧副本的表格行排在现行段落之前 |
| 受治理来源不一致时，回答要说出每一个值 | 一致：输入里留着一个无从选择的竞争值，回答就只能靠猜 | 两个值都在输入里且都没有标记时，治理后的长上下文只说了一方，24 个中答对 11 个（原始长上下文 21 个）；MVP 会在回答读取的内容里标出有争议的值 |
| 治理后的小输入让更弱、更便宜的模型也能回答 | 弱一致：没有竞争值时 3B 及以下的模型几乎全对，但它的查找比我们的问题简单得多 | 精简回答和成熟 RAG 答对一样多（各 233），输入 1,961 对 8,954 个 token；在 GPT-6 Luna 上，Inspiration 在共享盘测试集上与它持平（各 134） |
| 小输入更便宜、回答更快 | 没有涉及；而且仅仅变短并不会让回答更对 | 每个回答精简回答 0.0012 元对 0.0083 元，模型中位耗时 1.40 秒对 1.73 秒 |
| 治理花在模型调用和人的时间上的成本能收回 | 没有涉及；它暗示治理可以只做窄的一部分，因为只有同一事实的竞争值才损害准确率 | [治理成本与回答省下的钱](design/validation.md#治理成本与回答省下的钱)中的账本；没有"替我决定"时每 100 份文档 33 条待办 |

### 局限

- **竞争值没有任何可以用来选择的线索。** 竞争值和证据一样新、一样权威，所以有一个竞争值时模型只能猜，0.25 到 0.52 等于或低于抛硬币的 0.5。论文表明的是：没有解决的冲突会让回答不可靠；它没有表明模型无法处理双方都带日期和来源的冲突。成熟 RAG 的规则"优先受治理的来源，其次最新的文件"能处理其中很多，这就是为什么我们比它只高 5 到 7 个百分点，而不是论文数字所暗示的几十个百分点。
- 只有一个合成任务，模型都在 3B 参数及以下（7B 模型只出现在一个推理任务的复现中）；没有真实文档，也没有检索。它无法说明检索漏召回的问题，而在共享盘测试集上 Inspiration 输给成熟 RAG 的每一个回答都来自检索。
- 按作者自己的说法，结论是相关性的：没有对注意力做干预。在它的竞争性填充内容里，冲突的数量随长度增加，4,096 个 token 及以上的每个输入都至少有一个冲突，所以只是格式相同的陈述只在 2,048 个 token 以内测过。冲突分析没有预先注册。
- 一篇新的单作者预印本。Hugging Face 上的摘要写的是 0.16 到 0.33 和 45 个百分点，而全文是 0.11 到 0.21 和 46 个百分点，说明数字在修订之间变过；引用时注明读的是哪个版本。

### 我们能用上什么

- **治理该花在哪里。** 准确率损失来自同一事实的其他值，而不是内容一致的近似重复。这支持把治理集中在有不止一个值的事实槽上（变更、冲突、滞后的副本和翻译），并让内容一致的副本不进入人的审阅，这关系到治理成本，也就是我们的主要风险。
- **怎么表述。** "决定答案的是输入里有什么，而不是输入有多长"是一句恰当的概括，引用时注明这是基于合成任务的预印本。它不能作为我们领先幅度或成本的证据。
- **验证这条线恢复时。** 对每个问题和每种方案，数一数回答模型的输入里与答案键的值相竞争的值有几个（不花模型调用的钱，证据审计本来就读这些输入），看这个数能否跨方案预测答错的问题。如果能，在更大的数据集上就能在任何付费运行之前看出治理能赢下哪些问题。论文里的注意力指标需要开放权重，所以用不到我们用来回答的托管模型上。
