# GitLab 费用制度回放

一份真实的制度文档，按它六年来的编辑历史逐版回放，用来衡量知识在变化时抽取和治理的表现。文档是 GitLab 公开手册中的差旅与费用制度，取 2020 年 11 月到 2026 年 9 月之间的 21 个版本。回放把每个版本依次覆盖写入，引擎时钟设为该版本发布当天，执行 ingest，然后询问 governance 关于 14 个事实（酒店上限、每日餐费、收据门槛、报销期限等）会告诉读者什么。英文版见 [README.md](README.md)；两者不一致时以英文版为准。

```bash
pnpm bench replay examples/gitlab-expenses          # 内存中运行，约 6 秒
pnpm bench replay examples/gitlab-expenses --stack  # Postgres 和 Valkey
```

`apps/bench/test/history.test.ts` 在内存和 Postgres 上运行它，并要求结果与 `timeline.yaml` 一致。

## 文件

| 文件 | 内容 |
| --- | --- |
| `history/` | 21 个版本，与 GitLab 发布时逐字节一致，命名为 `<日期>-<commit>.md` |
| `history.yaml` | 按顺序排列的步骤：日期、版本、commit、该 commit 下页面的链接、commit 标题 |
| `timeline.yaml` | 每个事实从哪天起应当告诉读者什么，由人工阅读各版本得出；以及每个事实上引擎目前给出不同结果的地方和原因 |
| `vocabulary.yaml` | 14 个事实，表示为 9 个带限定词的谓词，措辞沿用制度原文 |
| `corpus.yaml`、`handbook/` | 一个受治理的文件夹来源；回放把各版本写到 `handbook/finance/expenses.md` |

## 来源与许可

各版本来自 GitLab 手册：2023 年 10 月之前是 `gitlab-com/www-gitlab-com` 中的
[`sites/handbook/source/handbook/finance/expenses/index.html.md`](https://gitlab.com/gitlab-com/www-gitlab-com/-/commits/master/sites/handbook/source/handbook/finance/expenses/index.html.md)，之后是 `gitlab-com/content-sites/handbook` 中的
[`content/handbook/finance/expenses.md`](https://gitlab.com/gitlab-com/content-sites/handbook/-/commits/main/content/handbook/finance/expenses.md)。它们 © GitLab Inc. 及贡献者，采用 [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/) 许可，原样复制；`history.yaml` 为每个版本链接到它的 commit。本目录其余文件由我们编写。

在两个仓库中该页面最近的 500 个 commit 里（旧仓库 200 个，最早到 2020 年 11 月；新仓库 300 个，最晚到 2026 年 9 月），保留的是 14 个事实中有事实变化、出现或消失的版本，以及不改变任何事实的编辑（仓库迁移、改名、薪资截止日期），这些编辑不应改变任何知识。只重复已保留变化的 commit 被略去，以缩短运行时间。

## 制度经历了什么

| 日期 | 所跟踪事实的变化 |
| --- | --- |
| 2020-11-17 | 保留的第一个版本。"Itemized receipts are required for all expenses"（门槛为 0）、"submitted within 30 days"、一张硬件表：外接显示器 $380，便携显示器 $200 |
| 2021-05-10 | 显示器 $400 |
| 2021-06-23 | 显示器 $500，超宽屏 $1,000 |
| 2021-12-03 | 页面重组；硬件表从页面上移除，制度摘要缩进了四个空格 |
| 2021-12-13 | 年终节日预算；与所跟踪事实无关 |
| 2022-01-20 | "Itemized receipts are required for all business related expenses that are greater than $75" |
| 2022-01-27 | "submitted within 90 days"；电话服务 "$200 monthly threshold" |
| 2022-05-31 | 页面重写并缩短；"Cell phone service is reimbursable up to $200" |
| 2023-02-08 | 重新要求所有费用都提供收据；电话 $50；每月上限 "$5K"；居家办公补贴新员工 $1,500、每年 $500，写在表格单元格中；不再写报销期限 |
| 2023-05-17 | "Expense claims over 90 days ... will not be reimbursed"；电话上限移入 HTML 表格，写作 "Policy is set at $50" |
| 2023-08-29 | 全球差旅与费用制度：酒店每晚 $300，餐费每天 $100，差旅中上网每天 $50，美国员工超过 $50 才需收据，每月上限 "$10K"，E-Group "$20K"，补贴写成句子；电话 "Policy is set at $80" |
| 2023-10-05 | 突出显示邮箱地址；与所跟踪事实无关 |
| 2023-10-16 | 页面迁到新的手册仓库；与所跟踪事实无关 |
| 2024-01-22、2024-02-06、2024-02-08 | 措辞修改；与所跟踪事实无关 |
| 2026-02-17 | 薪资截止日期；与所跟踪事实无关 |
| 2026-03-18 | 页面被替换为两行通知："This page has moved"，指向内部手册 |
| 2026-05-14 | 页面恢复，所跟踪事实不变 |
| 2026-06-19 | 餐费每天 $120；电话 "Policy is set at $100" |
| 2026-09-13 | HelpLab 改名为 Compass；与所跟踪事实无关 |

当某个版本不再写某个值、也没有给出新值时（硬件表、迁移通知），`timeline.yaml` 保留这个值：知识绝不会悄无声息地消失（[来源变更](../../docs/zh/design/source-changes.md)，规则 1），而本次回放中没有人将它退役。

## 运行结果

使用替身模型时，**294 个事实版本中有 174 个**（14 个事实 × 21 个版本）给出了应当告诉读者的值。这可以分成截然不同的两半：

- 制度尚未写出任何值的 82 个事实版本全部正确：没有凭空编造，不过有一条陈述落进了一个单独的槽位（见下文）。
- 制度写出了值的 212 个事实版本中，92 个正确。13 个给出了错误的值：`receipt_threshold` 两次从缩进摘要的上一行取了 "$5,000 USD"；`phone_service_monthly_cap` 在 11 个版本中保留 2023 年的 $50，而这些版本写的是 $80、后来是 $100，用的是替身模型读不出来的措辞。其余 107 个什么都没给出。

所有错误都来自替身模型；引擎负责的部分全部正确：

- 新版本在发布当天取代旧值：2022-01-27 报销期限从 30 天变为 90 天，2023-02-08 电话上限从 200 变为 50，2026-06-19 餐费从 100 变为 120。不改变任何事实的编辑不改变任何内容。
- 某个版本不再写明某个事实时，这个事实被保留，标记为“已不再写明”，文档的负责人收到一条待办，列出它不再写明的所有内容。2026-03-18 的迁移通知保留了页面上的全部九个事实，直到 2026-05-14 页面恢复，标记随之去掉，待办撤回。替身模型从 2023 年起读不出电话上限，所以它至今仍是 50，带着标记，而页面写的是 $100。保留事实是引擎的规则；读不出新值是替身模型的错误。

在引擎保留这类事实之前，结果是 294 个中的 165 个：迁移通知和替身模型不再读出的两个值让 9 个事实版本悄无声息地消失了，违背了[来源变更设计](../../docs/zh/design/source-changes.md)的规则 1。

这 120 个错误都是因为替身模型没有读出值。它只读取目录词语旁边的数字，而真实的制度文本往往不是这样写的。它会漏掉：

- 以千为单位的金额（"$10K"）；
- 带货币符号的表格单元格（"Average Price in USD" 下的 "$380"）；
- HTML 表格；
- 没有数字的规则（"required for all expenses"，即门槛为 0）；
- 目录之外的措辞（"**Phone** \| $200"，或用 "new Team Members" 指新员工）；
- 写在标题下的设定式上限（"Phone Service" 下的 "Policy is set at $80"），句子里既没有目录词语，也没有月份。

配置好真实模型后，应当再用同一份语料运行一次。届时这 120 个衡量的就是抽取质量。

真实文本还带来两个发现：

- **一条陈述落进了单独的槽位。** "providing new Team Members with a $1,500 USD ... stipend" 提到了补贴，但没有限定词的词语，于是它落进一个不带限定词的 `home_office_stipend` 槽位，与两个带限定词的槽位并列。检查把它报告为 `timeline.yaml` 没有列出的槽位。
- **一个过长的主题名会让整个回答的名称全部作废。** page compiler 的替身模型原先把英文名称截到 60 个字符，但 `name_topics` 的回答只允许 40 个，所以一个较长的真实标题使网关拒绝了整个回答，其中每个主题都退回到它的第一个标题（"no valid names for topics"）。英文语言包现在截到 40。真实模型也可能犯同样的错误，所以因为一个名称就拒绝整个回答的做法，值得在 page compiler 中重新考虑。

`timeline.yaml` 完整给出了每个事实的原因。某个改动弥补了其中一个差距时，历史测试会失败，直到删除那里对应的条目，所以每一次改进都会体现为该文件的一处 diff。

## 需要人做什么

回放还统计每个版本需要人来决定的事情（报告中的 `review` 和 `review:` 一行）。首次读取之后，20 个版本改变了 20 个事实：某个值出现、改变或不再写明。它们产生了 2 条待办，并两次给已打开的待办增加了要决定的内容（上一个版本时它没有列出的陈述），所以一共问了人 4 次，即每个改变的事实 0.2 次。其中一条待办在一周后无需人处理就撤回了。首次读取没有提出任何问题。

四次询问中只有一次值得人花时间，另外三次都来自替身模型：

- **2026-03-18，值得询问：** 页面变成迁移通知，已打开的待办列出它不再写明的九个事实。
- **2022-01-20，来自替身模型：** 收据门槛在 5,000 和 75 之间冲突，其中 5,000 是替身模型对缩进摘要的误读。下一个版本结束了冲突，待办随之撤回。
- **2023-02-08，来自替身模型：** "Items over 90 days from purchase date will not be reimbursed" 换了一种说法写报销期限，替身模型读不出来，于是两条 90 天的陈述被列为不再写明。
- **2023-05-17，来自替身模型：** 电话上限移进 HTML 表格，写作 "Policy is set at $50"，替身模型读不出来。页面此后继续写着这个上限，先是 $80，后来是 $100，待办一直开着。

统计还发现了一个属于引擎自身的问题，现已修复。2022-01-20 页面删去了制度摘要两份副本中的第二份，那里写的 30 天期限被列为不再写明，尽管页面在别处仍然写着它。现在，某条陈述的所在位置被删去时，由该版本仍然写明同一事实的现有陈述取代它，所以一个写了两次的事实少了一处时，不会再询问任何人。

为下一个基准（用这些版本搭建的共享盘测试集）编写答案时，发现了本例答案中的一个错误：`timeline.yaml` 曾把电话上限记为从 2023-08-29 起不再写明，而页面在 "Phone Service" 标题下写着 "Policy is set at $80"，后来是 $100。答案已经更正，结果因此从 185 变为 174，改变的事实从 18 个变为 20 个。一个人写的答案需要第二位读者核对，正如验证设计所要求的。
