# 公司网盘的真实样子

一家公司实际存放的文档，全部用真实的公开文本搭成，用来检验：当旧副本、旧修订版和滞后的译文就放在现行文档旁边时，引擎回答的是不是现在有效的内容。150 个问题，中、英、日文各三分之一，同时交给引擎和两个对手回答，用的是同样的文档和模型：一个是在同样的切块上做普通检索，另一个是把所有文档都读一遍的模型。英文版见 [README.md](README.md)；两者不一致时以英文版为准。

```bash
pnpm engine ingest examples/company-drive --today 2026-10-27 --context 1000000   # 在内存中运行，约 50 秒
```

`--context` 给长上下文对手一百万 token 的窗口：这个网盘有 311,106 个 token，超过默认的 150,000。`apps/engine/test/company-drive.test.ts` 逐条核对答案键与文件，并把运行结果固定为下面的数字。

## 网盘里有什么

每句话都保持作者原文，只有摆放方式是布置出来的。`files.yaml` 写明每个文件的来源、修订版、最后修改时间（加载时把这个时间设为文件的修改时间，就像网盘会显示的那样）以及它代表什么。

| 文件夹 | `corpus.yaml` 中的来源 | 内容 |
| --- | --- | --- |
| `handbook/finance/` | Handbook，受治理，权威度 0.9 | GitLab 2026-09-13 的差旅与报销制度，旁边是有人留下的 2024-02-08 版备份 |
| `../kubernetes-docs/docs/` | Engineering docs，受治理，0.9 | [examples/kubernetes-docs](../kubernetes-docs/) 的五个 Kubernetes 页面，各有英、中、日文，日文最多落后三年 |
| `drive/finance/`、`drive/downloads/` | Shared drive，参考，0.5 | 大家存下的报销制度旧副本：2023-02-08、2022-05-31 和 2021-06-23 |
| `drive/research/{en,ja,zh}/` | 同上 | 维基百科“新干线”条目的三种语言，各有当前修订版和 2024 年 10 月的一版 |

制度文件是 GitLab 页面在所列提交时的原样（© GitLab Inc. 及贡献者，[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)）。条目作者为维基百科贡献者，CC BY-SA 4.0：每个文件是所列修订版的 Parsoid HTML，只保留正文。保留的是条目正文、标题、段落、列表和表格（含信息框）以及图注，所有文字节点不变；去掉的是样式、参考文献标记和列表、导航框、隐藏的维护标记、编辑链接，以及 `href`、`lang`、`colspan`、`rowspan` 以外的属性。中文修订版取 zh-cn 变体。`.acl.yaml` 让整个租户都能读这两个文件夹；`vocabulary.yaml` 是 GitLab 和 Kubernetes 两个示例的词表，加上五个新干线谓词。

## 答案键

`keys.yaml` 列出 36 个事实，每个事实按生效日期列出各个值，每个值都写明网盘里在哪里说的：文件、修订版和原文。答案键是读文件写出来的，不是从引擎得来的。`asked_on`（2026-10-27）那天有效的值就是答案，其余的值都是过时的。日期来自文档本身或它的历史：制度取 GitLab 历史中这个值第一次出现的版本（[examples/gitlab-expenses](../gitlab-expenses/)）；条目取文中给出的日期（“fiscal 2023”记为 2024-03-31，“in 2024”记为 2024-01-01），否则取网盘上最早说到它的修订版。值为 `null` 表示从那天起没有在用的文档再说这个事实，但旧副本可能还在说：2021 年下载的那份仍列着显示器上限，而制度在当年 12 月就删掉了。

| 事实 | 未变 | 变过 |
| --- | --- | --- |
| 报销制度（只有英文） | 酒店、出差上网、美国员工收据、E-Group 上限、新员工补贴、给主人的礼物、礼品上限、联合办公、客户餐、国内航班提前预订 | 每日餐费 100 → 120、报销期限 30 → 90 天、每月上限 $5K → $10K、电话 200 → 50 → 80 → 100、家庭宽带 80 → 100、干洗 3 → 5 天、市场活动采购 2,500 → 5,000；显示器上限不再写明 |
| Kubernetes（三种语言） | 节点数、每节点 Pod 数、集群 Pod 数、kubelet 版本偏差、终止宽限期、回退上限与重置、imagefs 阈值 | 无 |
| 新干线（三种语言） | 最高速度、常规轮轨与磁浮纪录、开通日、座位数 | 札幌开通 2031 → 2038、东海道乘客 1.59 亿 → 1.61 亿、全规格线路长度 2,830 → 约 2,951 公里（只有日文条目落后）、中央新干线开通 2027 → 2034 |

核对一条时，打开 `files.yaml` 为该文件给出的链接（链接里带着修订版），找到原文，读出值和它的条件。测试只检查每段原文都在它的文件里（连续空白算一个空格，去掉 HTML 标签），以及修订版与 `files.yaml` 或 `examples/kubernetes-docs/sources.yaml` 一致；原文说的是否就是答案键说的，要靠人读。

## 问题

`questions.yaml` 对每个未变的事实每种语言问一次，对每个变过的事实问两次、换个说法，另有九个网盘里没有答案的问题（育儿假、ConfigMap 的大小、带宠物乘新干线），每种语言三个：共 150 个问题，每种语言 50 个，69 个问未变的事实，66 个问变过的，15 个是在用文档回答不了的。报销制度只有英文，所以它的 52 个中文和日文问题是跨语言提问，就像一家国际公司的员工会做的那样。

回答中含有现行值的文字，并引用了说出它的文档，算“对”（right）；含有旧值的文字而不含现行值，算“过时”（stale）。文字比较时不分大小写、不计千位分隔符，数字必须完整匹配（“30”不在“300”里）。对的回答也可能顺带提到旧值；换成真实模型后，需要评判者区分“90 天（一份旧副本写的是 30）”和含糊其辞的回答。

## 用替身模型的结果

所有模型任务都由替身回答，所以这些数字衡量的是流水线，不是模型质量。

| 问题 | 引擎：对，过时 | 普通检索 | 全部读一遍 |
| --- | --- | --- | --- |
| 全部 150 | 48，5 | 44，6 | 49，8 |
| 未变，69 | 32，0 | 32，0 | 34，0 |
| 变过，66 | 14，4 | 10，5 | 13，6 |
| 网盘答不了，15 | 2，1 | 2，1 | 2，2 |
| 英文，50 | 31，4 | 26，5 | 31，7 |
| 中文，50 | 11，1 | 10，1 | 10，0 |
| 日文，50 | 6，0 | 8，0 | 8，1 |

- 在替身读得懂文档的英文问题上，关于变过的事实，引擎 22 题答对 11 题、过时 3 题，普通检索 8 和 4，全部读一遍的模型 11 和 5；关于未变的事实，三者 23 题中分别答对 20、18、20。
- 治理在无人参与的情况下处理了副本：制度的 90 天和 $120 胜过备份和网盘上的副本。2021 年下载那份的“within 30 days”被判为过时，所以引擎用制度的 90 天回答，并注明一份较旧的文档写的是 30；普通检索则回答 30。
- 跨语言时替身几乎找不到：制度的 52 个中文和日文问题只答对一题。替身检索比较的是词和哈希向量，中文问题找不到英文句子；要衡量这一点，需要多语言的嵌入模型。
- 替身回答会写出与问题有四分之一词相同的任何句子，所以对 15 个在用文档答不了的问题，只有 2 个说“没有写明”，还给出了 2021 年副本里的显示器上限。
- 属于替身的过时回答：制度现行的电话上限（“Phone Service”下的“Policy is set at $100”）没有被读出，于是 2023 年副本的 $50 成立；新干线的谓词措辞宽泛，把年份和其他速度也当成了值。
- 属于引擎的过时回答：中央新干线的开通时间在词表里没有谓词，没有治理管它，于是条目的 2024 年修订版和当前版被同等看待。引擎还没有用上“一份文档是另一份的旧副本或旧修订版”这一信息。

设计中的通过标准针对真实模型。真实运行需要什么，见 [docs/design/validation.md](../../docs/design/validation.md)。
