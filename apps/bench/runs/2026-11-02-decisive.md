# 2026-11-02: the decisive test on DeepSeek

The test [the validation spec](../../../docs/design/validation.md#the-decisive-test) names to
decide whether statement-level governance pays: two topics of real public text with stale,
conflicting and distorted facts built in (`examples/decisive-test`, 92 facts, 276 questions),
inside a searched corpus of 17.8 million tokens, read once and then answered five ways on
`deepseek-flash` with thinking off. It ran from 2026-11-02 10:03 to 2026-11-03 14:09 UTC, off-peak,
within the CNY 23 the product owner approved. A Chinese copy is in
[2026-11-02-decisive.zh.md](2026-11-02-decisive.zh.md).

The product owner asked on 2026-11-03 that the process be kept as evidence, so the full record
is in the project's shared files, `inspiration/validation/runs/2026-11-02-decisive/`: the
process log with every decision, approval, mistake and cost (`process-log.md`, `.zh.md`), each
step's report and config, the DeepSeek balance at each step, the hand check of the answers
(`two-value-check.md`) and every model reply (`replies-2026-11-03.jsonl.gz`).

## Conclusions

- **Inspiration does not clear the bar.** It answers 239 of the 276 questions right, the mature
  RAG 233: +2.2 points, and +2.9 on the 204 changed or conflicting questions, where the aim was
  10. Resampling facts, the 95% interval of that gap is −2.9 to +9.3 points. Both answer 70 of
  the 72 control questions. The spec's decision table says what follows: under 10 points ahead
  of a mature RAG, keep a light layer (editions, dates, conflict notes) on a mature RAG or long
  context and drop statement-level governance. The product owner decides.
- **Reading everything answers most.** Raw long context, all of the question's topic in the
  window, answers 252: the only arm clearly ahead of the mature RAG (+6.9 points, interval +0.7
  to +13.4). With DeepSeek's prefix cache it costs no more an answer than Inspiration, but takes
  four times as long end to end on this machine.
- **Governance made long context worse: 243 against 252.** It helps on lagging copies and
  translations (36 against 32 of 36, 32 against 27 of 33), and loses more on changes announced
  outside the policy page (8 against 16 of 27) and on governed pages that disagree (13 against 21
  of 24). Both losses come from one provisional rule: when sources conflict, the more
  authoritative one holds "until a person decides", and nobody settled the 52 todos, since no
  person took part and "Decide for me" is not built. So the policy page's old value held over
  the announcement that changed it, and one governed page's value hid another's.
- **Bar 1's audit missed that loss**, counting all 276 right values kept: it accepted a value
  marked "disputed" and checked only the first of two governed values. This pull request makes
  it stricter (`demoted`, and every side of a disagreement).
- **The bench overcounted right answers by 12 for Inspiration.** Citation markers such as "[20]"
  matched expected values, and an answer naming the current value anywhere counted right even
  when it said the old one holds. Without the markers and after reading 126 answers by hand, the
  counts fell from 251, 244, 247, 262 and 263 to 239, 233, 233, 252 and 243.
- **The compact answer matches the mature RAG at a seventh of the cost.** 233 each, at CNY 0.0012
  against 0.0083 an answer and a median 1.40 s of model time against 1.73.

## What the run taught

The process log has each mistake as it happened; these are the lessons, the first six already in
the spec ("How runs stay cheap", item 5) or the bench:

1. A paid step starts with a free preflight of its exact command. The missing catalogue would
   have shown there; the first reading's CNY 6.64 bought nothing governance could use.
2. The bench refuses what it can detect: facts the catalogue lacks, a catalogue that names none,
   a reader who can see no document.
3. A run whose report counts is never resumed; it replays into a fresh database.
4. A change is priced exactly before paying for it, by a run that may only replay saved replies.
5. Jobs longer than two hours run as their own processes. The local embedding server is restarted
   before each long run (it grew to 11 GB and was stopped once), and a run refuses to start with
   less than 6 GB of disk free (a full disk stopped one).
6. A scoring rule counts only what it can be sure of.
7. **A score is read, not only counted.** Matching a value cannot tell "10 days, changed from 7"
   from "7 days; an announcement says 10, but the policy holds". Answers that name an old value
   beside the current one are read before a result is reported, and citation markers are
   removed before matching (this pull request).
8. **The audit checks how a value stands, and every side of a conflict** (this pull request).
9. **A run without people measures governance's provisional choices.** The report says so, and
   deciding, by a person or "Decide for me", is tested apart.
10. **Anything that grows with a run is written as a stream.** The reply export held 1.2 GB in one
    string and failed (this pull request).

Two engine faults surfaced on the way, both fixed: the in-memory permission graph scanned every
relationship for each document checked (#90), which also inflated every arm's latency, and the
reply export above.
