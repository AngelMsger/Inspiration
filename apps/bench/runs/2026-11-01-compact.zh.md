# 2026-11-01：精简回答、成熟 RAG 和快模型，按成本、准确率和延迟一起衡量

这是产品负责人在 2026-11-01 要求的一轮：把 Inspiration 的成本、准确率和延迟放在一起评价，以最便宜的服务商为主，另一家的便宜模型只用来补充结论。在共享盘测试集的 150 个问题上，先做一次免费的检索检查，然后在 DeepSeek 上跑（10 题试跑和全部问题），再用 GPT-6 Luna 在相同的来源上回答，最后在真实读取上做一次免费的证据核查。英文版见 [2026-11-01-compact.md](2026-11-01-compact.md)，两者不一致时以英文版为准。

## 结论

- **成熟 RAG 多答对几题；Inspiration 读得少得多，精简回答也更快。** 在 DeepSeek 上，150 题中：成熟 RAG 137，Inspiration 134，精简回答 128。精简回答平均读 2,075 个输入 token，是成熟 RAG 9,936 个的五分之一，费用是四分之一，它的模型回答中位数 1.32 秒，成熟 RAG 1.66 秒。Inspiration 的标准回答读 5,538 个 token，每次 0.0060 元，成熟 RAG 0.0104 元，但它的模型回答中位数 1.83 秒，比成熟 RAG 略慢。
- **Inspiration 输给成熟 RAG 的每一题，都出自两个已知原因之一。**
  - 共享盘上 2023 年的制度副本：规范化没有把它认作改了名的手册制度的旧版，所以它的 2,500 美元市场活动上限被当作现行值作答。Inspiration 3 题，精简回答 4 题（多了它的 80 美元网费上限）。这一项从[第二次运行](2026-10-27-whole.zh.md)起就在清单上。
  - 精简回答的两段原文：东海道线的年客运量只写在英文条目里，没有哪条陈述记着它，日文条目的两段原文把它挤掉了。4 题。另有一道日文的酒店问题答成了“没有写明”。用保存的翻译做的免费检索检查证实了这两点：精简回答的输入恰好缺这 5 题的答案。135 个有答案的问题中，精简回答的输入有 126 个，Inspiration 的有 131 个，成熟 RAG 的有 131 个。
  - 成熟 RAG 答错的题，Inspiration 一题也没有答对。在这个整齐的共享盘测试集上，治理比“先受治理来源、再最新文件”这条规则没有多答对任何一题，正如[决定性测试](../../../docs/zh/design/validation.md#决定性测试)所预料的；只有过时和冲突的案例才能显示治理多带来了什么。
  - 两个原因都没有免费的修法，见[运行之后的核查](#运行之后的核查)。
- **换成更便宜、更快的模型，Inspiration 与成熟 RAG 打平。** GPT-6 Luna，每百万输入 token 0.10 美元：Inspiration 150 题答对 134 题，和成熟 RAG 一样多，精简回答 129 题。换成较弱的模型，成熟 RAG 在很长的新干线条目上少答对 3 题。Inspiration 多答对 3 题，它们在 DeepSeek 上用了相邻的另一项补贴作答：超宽显示器的报销上限，现用文档都没有写明，成熟 RAG 用一份旧副本里的值作答。Luna 的回答时间几乎不随输入变化：中位数精简回答 1.07 秒，Inspiration 1.16 秒，成熟 RAG 1.18 秒。每次回答的费用分别为 0.00024、0.00059 和 0.00104 美元。
- **在这台机器上，大部分时间花在检索上。** 回答前的检索中位数 11.4 秒：CPU 重排 9.1 秒，翻译问题 1.1 秒。两种 RAG 方案都要付，长上下文不用。产品会在 GPU 上重排，所以这些秒数说明不了产品的延迟；各方案之间能比的只有回答模型的时间。
- **真实读取上的核查没有发现丢失的正确值。** 治理交给模型的内容为全部 135 个带键的问题保留了正确的值和它所在的文档，没有丢掉任何一个原始文档写着的值，也没有引用读者可读范围之外的文档；15 个“没有写明”的问题没有值可核查。它在只检索的检查里运行，不花钱。核查检查的是正确的值是否还在，而不是旧值是否被标出：2023 年副本的 2,500 美元仍被当作现行值交给模型。
- **费用：DeepSeek 2.95 元**（之前余额 101.56 元，之后 98.61 元），**OpenAI 0.28 美元**，按 OpenAI 公布的价格计量，因为用 API 密钥读不到它的余额。全部问题那次运行去掉了长上下文方案，省了约 4 元；它们的成本和延迟已经由试跑给出。

## 运行了什么

- **引擎。** PR #74 的 a34f532（精简回答，`Engine.compact`，`COMPACT_SOURCES` 为 2 段原文和 8 条陈述）；只检索的检查里的核查随本记录的 PR 一起提交。Luna 的配置 `config/gateway.luna.yaml` 在 PR #75 里。
- **模型。** DeepSeek 上的一切都用 `deepseek-flash`，关闭思考。Luna 只负责回答，用 `gpt-6-luna`，`reasoning_effort: none`，其他调用都重放 DeepSeek 那次运行的回复。Qwen3-Embedding-0.6B 和 bge-reranker-v2-m3 在本地 CPU 上运行。提示词：`answer_question@3`、`translate_question@1`，以及之前各次运行的阅读提示词，全部是重放。
- **命令**，每条都在新的数据库上运行，之前各次运行的回复已经在回复缓存里：

  ```bash
  # 免费：每种方案的输入里是否有答案
  pnpm bench ingest examples/company-drive --today 2026-10-27 \
    --gateway config/gateway.local-embeddings.yaml --stack --search-only
  # DeepSeek，先试跑再跑全部；全部问题那次去掉了长上下文方案
  pnpm bench ingest examples/company-drive --today 2026-10-27 --context 1000000 \
    --gateway config/gateway.deepseek.yaml --stack --questions 10 --json gate10.json
  pnpm bench ingest examples/company-drive --today 2026-10-27 --context 50000 \
    --gateway config/gateway.deepseek.yaml --stack --json full150.json
  # Luna，先试跑再跑全部，除回答外都是重放
  pnpm bench ingest examples/company-drive --today 2026-10-27 --context 50000 \
    --gateway config/gateway.luna.yaml --stack --questions 10 --json luna10.json
  pnpm bench ingest examples/company-drive --today 2026-10-27 --context 50000 \
    --gateway config/gateway.luna.yaml --stack --json luna150.json
  # 免费：真实读取上的证据核查
  pnpm bench ingest examples/company-drive --today 2026-10-27 --context 1000000 \
    --gateway config/gateway.local-embeddings.yaml --stack --search-only --json audit.json
  # 免费：同上，但用 DeepSeek 保存的翻译，让检索与付费运行一致
  pnpm bench ingest examples/company-drive --today 2026-10-27 --context 1000000 \
    --gateway config/gateway.luna.yaml --stack --search-only --json audit-translated.json
  ```

  Node 的 `fetch` 要设置 `NODE_USE_ENV_PROXY=1`，并在 `NODE_EXTRA_CA_CERTS` 里给出代理的 CA，才能访问 DeepSeek 和 OpenAI；第一次试跑在发出任何请求之前就失败了，没有花钱。
- **付费的部分。** 2026-11-01 是星期日，全天闲时。

  | 运行 | 付费的回答 | 输入 token | 来自前缀缓存 | 输出 token | 费用 |
  | --- | --- | --- | --- | --- | --- |
  | DeepSeek 试跑，10 题 | 50 次，另有 10 次翻译 | 4,917,457 | 4,347,648 | 5,822 | 0.68 元 |
  | DeepSeek，150 题 | 420 次，另有 140 次翻译 | 2,493,975 | 440,192 | 52,252 | 2.27 元 |
  | Luna 试跑，10 题 | 30 次 | 177,817 | 0 | 1,776 | 0.019 美元 |
  | Luna，150 题 | 420 次 | 2,483,465 | 0 | 23,835 | 0.260 美元 |

  其余都来自保存的回复：339 次抽取、42 次分块标题、话题命名，以及每个问题第一次检索之后的所有向量和重排分数。

## 运行之后的核查

2026-11-01，这份记录第一次汇报之后，两个原因都做了不花钱的核查，两处都没有修改。

- **只凭文本给改了名的副本配对并不安全。** 一条规则：标题不同的候选，只要 SimHash 相差不超过 9 位、相同文本至少 20%，就接受。在共享盘测试集上它把 2023 年副本和 2024 年备份配成一对，此外在共享盘测试集、演示语料、对照语料和 Kubernetes 上都没有别的变化。但在一个 1,500 份文档的合成语料上，它还把 35 对用同一模板写的不同制度配成一对，它们相同的文本可达一半（同一部门的账号安全和设备丢失管理办法），检索随后会把一份受治理的制度藏在它的“兄弟”后面。
- **市场活动那几题丢在检索上。** 现行制度把“低于 $5,000”写在一段 1,822 个字符、讲笔记本电脑的原文末尾。对英文问题，任何一条路径的前 16 段原文里都没有它；排在最前的是 2023 年和 2022 年副本的表格行。这 6 题里成熟 RAG 答对 3 题，只是因为碰到了 2024 年备份里那段讲笔记本电脑的原文，而 Inspiration 把那份备份视为已被现行制度取代。
- **让两段原文来自两份文档，没有收获。** 精简回答的两段原文改为取自不同文档后，它的输入在 135 题中仍有 126 题含答案（得 2 失 2）。东海道线的年客运量 1.59 亿人次只有英文条目的 2024 年版写着，现行版已不再写。

所以重跑回答不会有变化；规格说明的下一步是两个话题的案例。
