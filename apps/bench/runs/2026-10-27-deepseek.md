# 2026-10-27: first run on DeepSeek

The first runs of the engine on a real model, following the plan in
[docs/design/validation.md](../../../docs/design/validation.md): a smoke test on the demo
corpus, the company drive with 10 questions as a gate, then with all 150, then the GitLab
replay. A Chinese copy is in [2026-10-27-deepseek.zh.md](2026-10-27-deepseek.zh.md).

## Conclusions

- **Reading is much better than with the stand-ins, and still below the proposed bar.**
  - Company drive: recall 77% (59 of 77 keyed values), precision 53%. The stand-ins scored
    55% and 14%; the bar is 85% and 90%.
  - One slot, `shinkansen_max_operating_speed`, takes 44 of the 53 values no key gives: the
    catalogue offers only the network's top speed, so the model files every line's top speed
    under it. Without that slot, recall is 78% and precision 86%.
  - GitLab replay: 249 of 294 slot-versions right (85%); the stand-ins got 174 (59%).
  - The misses left are real reading misses: amounts in a sentence that names neither the
    catalogue's words nor the unit ("Policy is set at $80" under "Phone Service"), and figures
    in the older copies of the expense policy.
- **Answering is decided by search, and search still runs on stand-ins.**
  - Right answers of 150: the engine 71, plain retrieval 60, a model reading every document
    140.
  - Where search found the expected text (64 of the 135 questions with an answer), the engine
    answered 58 right (91%). Where it did not, it answered none.
  - The stand-in embeddings and reranker fail across languages: the engine got 34 of 50
    English questions right, and 19 of 50 Japanese and 18 of 50 Chinese.
  - On changed facts the engine beats plain retrieval by 11 points (18 against 11 of 66), not
    the 20 the bar asks. Stale answers: engine 3, plain retrieval 3, reading everything 0.
- **Reading everything is the strongest rival at this size, but not on facts no longer
  stated.** The drive is 311,000 tokens, inside the 1M window, and with the prefix cache a
  question costs about CNY 0.006. It answered 62 of 66 changed facts with no stale answer. On
  the 15 facts the current documents no longer state, though, it gave 6 stale answers, and the
  engine none (13 right): marking what is no longer stated is where governance shows.
- **Asking little holds.** The replay raised 2 todos and gave open todos more to decide 5 times
  over 20 changed facts: 0.35 asks per changed fact, against a bar of at most 1. Whether each
  was worth asking needs a reviewer.
- **Cost is small and predictable.** All of the day's paid calls cost CNY 6.6 (about US$0.93).
  With the replies kept, the 150 questions cost CNY 1.33, since reading the drive came from the
  cache.
- **Two engine faults were found and fixed.** Postgres rejected a claim citing two quotes from
  one span (the fix is in PR #49); topic names over 40 characters failed the whole naming call
  (PR #51).

## What ran

- **Model** `deepseek-flash` (the API lists it as DeepSeek-V4.1-Flash, with a context window
  of 1,048,576 tokens). It thinks by default, which bills its reasoning as output; the config
  turns that off with `request: {thinking: {type: disabled}}`.
- **Config** `config/gateway.deepseek.yaml` with `limit: 2` for the day.
- **Prompt versions** `extract_claims@4`, `write_context@1`, `name_topics@2`,
  `answer_question@2`.
- **Stack** `make up` on one 4-vCPU container, a fresh database for each run.

| Run | Commit | Command | UTC |
| --- | --- | --- | --- |
| Smoke test | `3efc581` | `pnpm bench ingest examples/corpus --today 2026-10-27 --gateway <config> --stack` | 11:56 |
| 10 questions | `3efc581` | `pnpm bench ingest examples/company-drive --today 2026-10-27 --context 1000000 --gateway <config> --stack --questions 10` | 12:05 to 12:35 |
| 150 questions | `57d985e`: `3efc581` with the fix of PR #49 | the same without `--questions`, after `pnpm bench cache import` | 12:42 to 13:00 |
| GitLab replay | the same | `pnpm bench replay examples/gitlab-expenses --gateway <config> --stack` | 13:07 to 13:33 |

Each run had a dry run of the same command first. All ran off-peak by the published hours.
Reading the drive takes 28 minutes: 338 windows one after another, 4.5 seconds per call on
average.

**Kept** in the project's shared files under `inspiration/validation/runs/2026-10-27/`: the
1,358 replies of all four runs (`replies.jsonl`), the JSON and text reports of each run and
its dry run, every metered call (`usage.csv`), the config and the error logs. The smoke test
was run a second time on a fresh database after importing its replies: it made no paid call.

## What it cost

DeepSeek bills this account in CNY, and its price page cannot be reached from the
container, so the prices were measured from the balance (`GET /user/balance`) around calls
of known size: CNY 1 per million input tokens, CNY 4 per million output tokens and about
CNY 0.02 per million cached input tokens, at 12:00 UTC. At about 7.1 CNY to the US dollar
that is half the peak prices in the config, as DeepSeek's off-peak discount would make it;
the peak prices were not measured.

| Run | Calls paid | Input tokens | From the prefix cache | Output tokens | CNY |
| --- | --- | --- | --- | --- | --- |
| Price probes and smoke test | | | | | 0.63 |
| 10 questions | 421 | 3,687,196 | 2,673,152 | 418,797 | 2.74 |
| 150 questions | 436 | 40,272,684 | 39,893,376 | 38,703 | 1.33 |
| GitLab replay | 468 | 673,998 | 137,728 | 342,892 | 1.91 |
| **All** | | | | | **6.61** |

- The 10-question run read the whole drive, and extraction was three quarters of its cost:
  the model writes about 1,150 tokens per window, twice the stand-in, so the dry run's
  extraction estimate was half the real one.
- In the 150-question run, all 339 extraction calls and the 10 earlier long-context answers
  came from the response cache. The long-context rival sends the whole drive, about 285,000
  tokens, with every question: after the first call, each call got 284,544 of them from
  DeepSeek's prefix cache (99.9%).
- The replay read 448 windows over the 21 versions, against about 1,000 for reading every
  version in full: extraction rereads only what an edit changes, and 15 of the 20 edits
  change more than a quarter of the text. Small edits read few windows (2023-10-16 changes 3%
  and reads 1). The one over-read is 2023-10-05: a renamed title and re-levelled sections
  change every block's headings, so a 28% edit reads 49 windows, about CNY 0.16 more.

## Next

1. **Real embeddings and reranking** (free, once a model can be downloaded from `*.hf.co`).
   Search decides the engine's answers, so this is the next measurement; rerunning the
   answers costs about CNY 0.5 with the replies kept.
2. **A per-line slot for top speeds**, measured as a pre-registered design change. It changes
   the extraction prompt, so it means one more paid reading of the drive (about CNY 2).
3. **Re-read less when only headings change.** A renamed title or re-levelled sections
   re-read every block under them (2023-10-05: 49 windows for a 28% edit). Measure the
   reading quality before changing it.
4. **A reviewer's verdict on the replay's 7 asks**, for the "worth asking" half of claim 4.
