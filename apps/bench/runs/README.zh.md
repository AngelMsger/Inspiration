## 记录里有什么

- **结论先行**：这次运行确定了什么，还有什么没定。
- **跑了什么**：提交号、完整命令、网关配置（含模型 ID 和请求参数）、每个任务的提示词版本。
- **花了多少**：按任务列出的 token 数，其中多少来自服务商的前缀缓存、多少来自响应缓存；真实扣费按服务商余额的前后差计算。
- **结果**，与同一命令在替身模型下的数字并列。

记录是存档：运行报告之后不再修改，除非要链接到推翻某个结论的新运行。

## 复用一次运行的回复

网关会缓存它收到的每条回复（网关配置中的 `cache`），键由模型、请求参数、任务、提示词版本和消息共同决定。运行结束时导出这些回复，连同 JSON 报告一起存进项目共享文件的 `inspiration/validation/runs/<date>/` 下，因为跑它的容器不会长久保留。下次运行前先导入：

```bash
pnpm bench cache import <replies.jsonl> --stack --gateway config/gateway.deepseek.yaml
pnpm bench ingest examples/company-drive ... --stack     # 只为之前没调用过的请求付费
pnpm bench cache export <new replies.jsonl> --stack
```

只有键变了才会重新付费：提示词换了版本、换了模型或请求参数、或窗口里的文字变了。所以修了回答环节只会重跑提问，修了某个提示词只会重读那个提示词读的内容。
