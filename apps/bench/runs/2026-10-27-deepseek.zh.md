# 2026-10-27：首次在 DeepSeek 上运行

引擎第一次在真实模型上运行，按 [docs/design/validation.md](../../../docs/design/validation.md) 的计划：先在演示语料上做冒烟测试，再用公司网盘的 10 个问题做门槛检查，然后跑全部 150 个问题，最后做 GitLab 历史回放。英文版见 [2026-10-27-deepseek.md](2026-10-27-deepseek.md)；两者不一致时以英文版为准。

## 结论

- **阅读比替身模型好得多，但仍未达到提议的标准。**
  - 公司网盘：召回率 77%（77 个标注值中找到 59 个），精确率 53%。替身模型是 55% 和 14%；标准是 85% 和 90%。
  - 标注之外的 53 个值中，有 44 个落在同一个槽位 `shinkansen_max_operating_speed`：目录只提供全网最高速度这一项，所以模型把每条线路的最高速度都归到它下面。去掉这个槽位，召回率 78%，精确率 86%。
  - GitLab 回放：294 个“槽位 × 版本”中对了 249 个（85%）；替身模型是 174 个（59%）。
  - 剩下的是真实的阅读失误：金额所在的句子既没用目录里的词，也没写单位（“Phone Service”标题下的“Policy is set at $80”），以及费用政策旧副本中的数字。
- **回答由检索决定，而检索仍在用替身。**
  - 150 题答对数：引擎 71，普通检索 60，读全部文档的模型 140。
  - 检索找到预期原文的题目（135 道有答案的题中 64 道），引擎答对 58 道（91%）；没找到的，一道也没答对。
  - 替身向量和替身重排跨语言基本失效：英文 50 题引擎答对 34，日文 50 题 19，中文 50 题 18。
  - 在已变化的事实上，引擎比普通检索高 11 个百分点（66 题中 18 对 11），没达到标准要求的 20 个点。过时回答：引擎 3，普通检索 3，读全部文档 0。
- **在这个规模上，读全部文档是最强的对照组，但在“已不再写明”的事实上不是。** 网盘共 311,000 个 token，在 100 万的窗口之内；有前缀缓存时每题约 CNY 0.006。它答对了 66 道已变化事实中的 62 道，且没有过时回答。但在当前文档已不再写明的 15 个事实上，它给出了 6 个过时回答，而引擎一个也没有（答对 13）：标记“已不再写明”正是治理发挥作用的地方。
- **“少打扰人”成立。** 回放在 20 个已变化的事实上提出了 2 个待办，并 5 次给未决待办追加了需要决定的内容：每个变化的事实 0.35 次询问，标准是不超过 1 次。每次询问是否值得，还需要人来评判。
- **费用低且可预测。** 当天全部付费调用共花 CNY 6.6（约 US$0.93）。由于保留了回复，150 题的运行只花了 CNY 1.33，读网盘的部分全部来自缓存。
- **发现并修复了引擎的两个问题。** Postgres 拒收引用同一片段两段原文的陈述（PR #49 已修复）；主题名超过 40 个字符会让整次命名调用失败（PR #51）。

## 跑了什么

- **模型** `deepseek-flash`（API 列出的名字是 DeepSeek-V4.1-Flash，上下文窗口 1,048,576 个 token）。它默认开启思考，思考内容按输出计费；配置用 `request: {thinking: {type: disabled}}` 关掉了。
- **配置** `config/gateway.deepseek.yaml`，当天预算改为 `limit: 2`。
- **提示词版本** `extract_claims@4`、`write_context@1`、`name_topics@2`、`answer_question@2`。
- **环境** 一个 4 核容器上用 `make up` 起的整套服务，每次运行用全新的数据库。

| 运行 | 提交 | 命令 | UTC |
| --- | --- | --- | --- |
| 冒烟测试 | `3efc581` | `pnpm bench ingest examples/corpus --today 2026-10-27 --gateway <config> --stack` | 11:56 |
| 10 个问题 | `3efc581` | `pnpm bench ingest examples/company-drive --today 2026-10-27 --context 1000000 --gateway <config> --stack --questions 10` | 12:05 至 12:35 |
| 150 个问题 | `57d985e`：`3efc581` 加上 PR #49 的修复 | 同上，去掉 `--questions`，先 `pnpm bench cache import` | 12:42 至 13:00 |
| GitLab 回放 | 同上 | `pnpm bench replay examples/gitlab-expenses --gateway <config> --stack` | 13:07 至 13:33 |

每次运行前都先对同一命令做了试运行。全部在公布的低峰时段运行。读完网盘要 28 分钟：338 个窗口逐个调用，平均每次 4.5 秒。

**留存**在项目共享文件的 `inspiration/validation/runs/2026-10-27/` 下：四次运行的全部 1,358 条回复（`replies.jsonl`）、每次运行及其试运行的 JSON 和文本报告、每次计量的调用（`usage.csv`）、配置和错误日志。导入冒烟测试的回复后在全新的数据库上重跑了一次：没有产生付费调用。

## 花了多少

DeepSeek 对这个账户按人民币计费，容器又访问不到它的价格页，所以价格是在已知大小的调用前后读余额（`GET /user/balance`）测出来的：UTC 12:00 时，每百万输入 token CNY 1，每百万输出 token CNY 4，每百万缓存命中的输入 token 约 CNY 0.02。按约 7.1 人民币兑 1 美元，这正好是配置中高峰价的一半，与 DeepSeek 的低峰折扣一致；高峰价没有测。

| 运行 | 付费调用 | 输入 token | 来自前缀缓存 | 输出 token | CNY |
| --- | --- | --- | --- | --- | --- |
| 测价调用和冒烟测试 | | | | | 0.63 |
| 10 个问题 | 421 | 3,687,196 | 2,673,152 | 418,797 | 2.74 |
| 150 个问题 | 436 | 40,272,684 | 39,893,376 | 38,703 | 1.33 |
| GitLab 回放 | 468 | 673,998 | 137,728 | 342,892 | 1.91 |
| **合计** | | | | | **6.61** |

- 10 个问题的运行读了整个网盘，其中四分之三的费用是抽取：模型每个窗口输出约 1,150 个 token，是替身的两倍，所以试运行对抽取费用的估计只有实际的一半。
- 150 个问题的运行中，339 次抽取调用和之前的 10 次长上下文回答都来自响应缓存。长上下文对照组每个问题都发送整个网盘，约 285,000 个 token：第一次调用之后，每次调用都有 284,544 个 token 来自 DeepSeek 的前缀缓存（99.9%）。
- 回放中，21 个版本每个都重读了约 20 个窗口，几乎是整份文档，尽管大多数版本只改了几行：448 次抽取调用中只有 29 次来自响应缓存。

## 下一步

1. **真实的向量和重排模型**（免费，只要能从 `*.hf.co` 下载模型）。引擎的回答由检索决定，所以这是下一项要测的；保留回复的情况下，重跑回答约 CNY 0.5。
2. **按线路区分的最高速度槽位**，作为预先登记的设计变更来测。它会改变抽取提示词，所以需要再付费读一遍网盘（约 CNY 2）。
3. **文档变化时按窗口复用。** 每个新版本都重读全部窗口，意味着持续监听时每次编辑都要付一次完整阅读的费用。
4. **由人评判回放中的 7 次询问**，补上第 4 条主张中“值得问”的那一半。
